<Phase type="concept">

## Шлюз как дирижёр

Стек соединяет несколько инструментов: primary для тонких задач, floor для работы без сети и fast-path для простого бойлерплейта. LiteLLM — дирижёр: агент обращается к одной точке, а шлюз распределяет промпты по порядку и переключается на fallback.

## Trade-offs честно

Никакой стек не «лучше» — у каждого свои стороны:

| Аспект | Claude Code | Sovereign | Cloud-OSS | Behind-GFW |
|---|---|---|---|---|
| **Качество out-of-box** | 9/10 | 7/10 | 7/10 | 6/10 |
| **Настройка** | 5 мин | пол-дня на учебный минимум (локальный LiteLLM + одна локальная модель); полный стек — недели | 30 мин | 1 час |
| **Цена/мес** | $20+ | $0 + железо | $0–5 | $0 |
| **Privacy** | низкая | максимальная | средняя | средняя |
| **Скорость** | средняя | высокая (local) | переменная | очень высокая (Cerebras) |
| **Vendor lock-in (зависимость от одного поставщика)** | Anthropic | нет | OpenRouter/провайдер | Cerebras/Google |
| **Доступ в Китае** | требует VPN | работает | переменно | работает |

## Decision tree (если всё ещё в сомнениях)

```
Ты в Китае без VPN?
├── ДА → Behind-GFW
└── НЕТ
    │
    Бюджет $20+/мес и не критична приватность?
    ├── ДА → Claude Code
    └── НЕТ
        │
        Есть GPU или Mac M-series?
        ├── ДА + важна автономность → Sovereign
        └── НЕТ → Cloud-OSS
```
