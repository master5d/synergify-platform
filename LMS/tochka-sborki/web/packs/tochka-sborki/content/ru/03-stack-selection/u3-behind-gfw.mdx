## Карта доступов

Стек Behind-Firewall (раньше в курсе — Behind-GFW, по китайскому «Великому файрволу») годится везде, где AI-сервисы закрыты государственной фильтрацией или самими вендорами. Ниже две карты: Китай и Россия.

### Китай

Без VPN в материковом Китае не работают Claude, OpenAI, большинство AI-IDE, AI Studio и Hugging Face; GitHub и npm требуют зеркал. Cerebras нужно проверять самостоятельно, а DeepSeek, Qwen и локальные модели — доступные опоры. В 2026 году Qwen, DeepSeek и GLM — сильные открытые модели; местные провайдеры часто принимают WeChat Pay и Alipay.

### Россия

Claude, OpenAI и Gemini (AI Studio) закрыты для России самими компаниями: они не обслуживают пользователей из РФ, и VPN этого не меняет — вход через VPN нарушает их условия, аккаунты блокируют. Российские карты не принимают и остальные зарубежные провайдеры. DeepSeek из России открывается, но пополнить его API-баланс российской картой официального способа нет. Доступные опоры — GigaChat от Сбера (у физлиц есть бесплатный режим, условия сверь при регистрации), YandexGPT в Yandex Cloud (оплата российской картой) и локальные модели. Про доступ к Cerebras из России официальных данных нет — проверь сам.

### Как узнать файрвол по симптомам

Файрвол выдаёт себя так: TCP-соединение с сервером устанавливается, а TLS-рукопожатие обрывается по таймауту, причём сразу на разных доменах одного сервиса. Смена клиента и отключение IPv6 не помогают: дело не в твоём компьютере, а в фильтре на стороне провайдера (в России — ТСПУ).

С июня 2025 года российские провайдеры ещё и режут соединения с сайтами за Cloudflare: часто проходят только первые 16 КБ, и страница грузится наполовину. Этот курс тоже работает через Cloudflare — если юнит открылся не целиком, причина та же.

> ⚠️ Чинить VPN этот юнит не учит: в России с марта 2024 года запрещена популяризация способов обхода блокировок, в Китае VPN — серая зона. Стек ниже VPN не требует.

## ⚡ Быстрая установка стека Behind-Firewall (одной строкой)

Одна команда ставит LiteLLM-прокси и агента Hermes (официальным установщиком Nous Research), пишет готовый конфиг (Cerebras + Gemini Flash) и подключает Hermes к шлюзу. В Китае Gemini не работает — после установки замени его на китайского провайдера (шаг 2); для России у установщика есть свой режим (ниже). Ниже — разбор по шагам, если хочешь понять, что происходит.

<OsToggle />

<OsBlock os="mac">

```bash
curl -fsSL https://ai.synergify.com/install-gfw.sh | bash
```

</OsBlock>

<OsBlock os="windows">

```powershell
irm https://ai.synergify.com/install-gfw.ps1 | iex
```

</OsBlock>

> 💡 На Linux работает та же команда, что и для Mac (`curl … | bash`).

**В России** запусти установщик в режиме России — он сразу запишет GigaChat вместо Gemini (шаг 2б) и подскажет, какой ключ вписать:

<OsBlock os="mac">

```bash
curl -fsSL https://ai.synergify.com/install-gfw.sh | bash -s -- --ru
```

</OsBlock>

<OsBlock os="windows">

```powershell
$env:GFW_REGION = 'ru'; irm https://ai.synergify.com/install-gfw.ps1 | iex
```

</OsBlock>

> ⚠️ Это тоже запуск чужого скрипта одной строкой. Если хочешь сначала его прочитать, сделай как в модуле 02: скачай в файл, открой, потом запусти.

После установки: впиши ключи провайдеров в `~/.config/litellm/.env`, запусти `start.sh`/`start.ps1`, а в другом терминале — `hermes`. Установщик уже записал в `.env` ключ шлюза `LITELLM_MASTER_KEY` (свежий LiteLLM без него не стартует) и передал его Hermes. Установщику Hermes нужен доступ к `hermes-agent.nousresearch.com` и GitHub; если он не прошёл, шлюз всё равно работает — проверь его командой curl из практики, а Hermes поставь по шагу 5, когда сеть позволит.

## Архитектура «Behind-Firewall»

```
┌─────────────────────────────────────────────────────────┐
│  Агент: Hermes (или любой OpenAI-совместимый)           │
├─────────────────────────────────────────────────────────┤
│  Router: LiteLLM (localhost:4000)                       │
│  ┌────────────────────────────────────────────────────┐ │
│  │ fast-path:  Cerebras gpt-oss-120b                  │ │
│  │ balanced:   актуальная модель Gemini Flash (сверь имя в консоли) │ │
│  │ местный:    DeepSeek/Qwen (CN), GigaChat (RU)      │ │
│  │ floor:      local llama-server (Qwen3-Coder-30B)   │ │
│  └────────────────────────────────────────────────────┘ │
└─────────────────────────────────────────────────────────┘
```

## Шаг 1: Cerebras (главный free-tier)

1. Зайди на [cerebras.ai/cloud-inference](https://cerebras.ai/cloud-inference) — официальных данных о доступе из Китая нет — проверь сам
2. Регистрация через email. Условия пробного тарифа меняются: сейчас для бонусных кредитов нужно привязать карту
3. Лимиты пробного тарифа (сейчас около 1M токенов в день) сверь на странице Rate Limits в документации Cerebras — они часто меняются
4. Получи API key → сохрани в `~/.config/litellm/.env` (тот же файл, что у быстрой установки):

```bash
# ~/.config/litellm/.env
CEREBRAS_API_KEY=csk-xxxxx
```

## Шаг 2: Google Gemini Flash (backup для долгих задач)

1. `aistudio.google.com` официально недоступен из материкового Китая и из России. Если ты в Китае — поставь на эту роль китайского провайдера (DeepSeek API или Qwen API). Если в России — переходи к шагу 2б. Если нет — возьми ключ в AI Studio и допиши его в тот же `.env`: `GOOGLE_API_KEY=...`
2. Бесплатные лимиты Gemini меняются — смотри их в своём AI Studio, а не по цифрам из юнита

## Шаг 2б: GigaChat вместо Gemini (Россия)

1. Зарегистрируйся в GigaChat API на [developers.sber.ru](https://developers.sber.ru/docs/ru/gigachat/tariffs/individual-tariffs) и создай проект. Бесплатный режим для физлиц и его лимиты сверь там же: условия меняются
2. Скопируй из проекта ключ авторизации (это `Client ID:Client Secret` в base64) и допиши в тот же `.env`:

```bash
# ~/.config/litellm/.env
GIGACHAT_CREDENTIALS=ключ-авторизации
```

3. В конфиге шага 3 поставь на роль `balanced` GigaChat вместо Gemini (установщик в режиме России уже записал этот блок):

```yaml
  - model_name: balanced
    litellm_params:
      model: gigachat/GigaChat-2-Lite   # сверь имена моделей в кабинете GigaChat
      api_key: os.environ/GIGACHAT_CREDENTIALS
      ssl_verify: false
```

> ⚠️ `ssl_verify: false` советует документация LiteLLM: сертификат GigaChat выпущен российским удостоверяющим центром, которого нет в стандартном наборе доверенных. Строка выключает проверку сертификата — держи её только в блоке GigaChat. Провайдер `gigachat/` есть в свежих версиях LiteLLM: если его нет, обнови `pip install -U 'litellm[proxy]'`.

> 💡 Автор курса этот путь из России сам не проходил (октябрь 2026): конфиг взят из документации LiteLLM. Если что-то не сходится — пиши в обратную связь, поправим.

## Шаг 3: LiteLLM gateway

Это «один endpoint для всех провайдеров». Устанавливается локально:

<OsToggle />

<OsBlock os="mac">

```bash
pip install 'litellm[proxy]'
mkdir -p ~/.config/litellm
```

</OsBlock>

<OsBlock os="windows">

```powershell
pip install 'litellm[proxy]'
New-Item -ItemType Directory $HOME\.config\litellm -Force
```

</OsBlock>

Минимальный конфиг `~/.config/litellm/config.yaml`:

```yaml
model_list:
  - model_name: fast-pool
    litellm_params:
      model: cerebras/gpt-oss-120b      # сверь с актуальным каталогом Cerebras
      api_key: os.environ/CEREBRAS_API_KEY

  - model_name: balanced
    litellm_params:
      model: gemini/gemini-2.5-flash    # в Китае замени на китайского провайдера
      api_key: os.environ/GOOGLE_API_KEY

  - model_name: local-floor
    litellm_params:
      model: openai/qwen-3-coder
      api_base: http://localhost:8080/v1
      api_key: not-needed

router_settings:
  routing_strategy: simple-shuffle
  fallbacks:
    - fast-pool: ["balanced", "local-floor"]
    - balanced: ["local-floor"]
```

Запуск. LiteLLM берёт ключи из переменных окружения (`os.environ/...` в конфиге), поэтому сначала загрузи `.env`. Свежий LiteLLM не стартует без собственного ключа шлюза `LITELLM_MASTER_KEY` — первая строка ниже создаёт его один раз. `--host 127.0.0.1` закрывает шлюз от остальной сети:

<OsBlock os="mac">

```bash
echo "LITELLM_MASTER_KEY=sk-$(od -An -tx1 -N24 /dev/urandom | tr -d ' \n')" >> ~/.config/litellm/.env   # один раз
set -a; source ~/.config/litellm/.env; set +a
litellm --config ~/.config/litellm/config.yaml --port 4000 --host 127.0.0.1
```

</OsBlock>

<OsBlock os="windows">

```powershell
Add-Content $HOME\.config\litellm\.env ("LITELLM_MASTER_KEY=sk-" + [guid]::NewGuid().ToString("N") + [guid]::NewGuid().ToString("N"))   # один раз
Get-Content $HOME\.config\litellm\.env | ?{ $_ -match '^\s*[^#].*=' } | % { $k,$v = $_ -split '=',2; Set-Item "env:$k" $v }
litellm --config $HOME\.config\litellm\config.yaml --port 4000 --host 127.0.0.1
```

</OsBlock>

Теперь все агенты могут смотреть на `http://localhost:4000` как на «OpenAI-compatible API».

## Шаг 4: Local fallback (llama-server)

На случай если все клауды лягут одновременно (бывает):

Качаем модель (через зеркало HuggingFace) для Китая: https://hf-mirror.com заменяет huggingface.co. Если huggingface.co не открывается в России — попробуй то же зеркало.

<OsBlock os="mac">

```bash
curl -LO https://hf-mirror.com/Qwen/Qwen3-Coder-30B-A3B-Instruct-GGUF/resolve/main/Qwen3-Coder-30B-A3B-Instruct-Q4_K_M.gguf
```

</OsBlock>

<OsBlock os="windows">

```powershell
Invoke-WebRequest -Uri "https://hf-mirror.com/Qwen/Qwen3-Coder-30B-A3B-Instruct-GGUF/resolve/main/Qwen3-Coder-30B-A3B-Instruct-Q4_K_M.gguf" -OutFile "Qwen3-Coder-30B-A3B-Instruct-Q4_K_M.gguf"
```

</OsBlock>

Запускаем llama-server (нужен llama.cpp):

```bash
llama-server -m Qwen3-Coder-30B-A3B-Instruct-Q4_K_M.gguf --port 8080 -c 65536
```

> 💡 Для Qwen3-Coder-30B нужно 32 ГБ RAM: файл Q4_K_M занимает примерно 18–19 ГБ, и ещё несколько гигабайт уходит на контекст. На 16 ГБ возьми модель до 8B. `-c 65536` — потому что Hermes требует у модели контекст от 64K токенов, а по умолчанию llama-server даёт меньше.

## Шаг 5: Подключаем агента

Агент курса — Hermes ([NousResearch/hermes-agent](https://github.com/NousResearch/hermes-agent)), им пользуется автор. Установщик из быстрой установки уже подключил его к шлюзу. Вручную — так:

<OsBlock os="mac">

```bash
curl -fsSL https://hermes-agent.nousresearch.com/install.sh | bash   # официальный установщик
hermes config set model.provider custom
hermes config set model.base_url http://127.0.0.1:4000/v1
hermes config set model.default fast-pool
hermes config set model.key_env LITELLM_MASTER_KEY
grep '^LITELLM_MASTER_KEY=' ~/.config/litellm/.env >> ~/.hermes/.env
hermes
```

</OsBlock>

<OsBlock os="windows">

```powershell
iex (irm https://hermes-agent.nousresearch.com/install.ps1)   # официальный установщик
hermes config set model.provider custom
hermes config set model.base_url http://127.0.0.1:4000/v1
hermes config set model.default fast-pool
hermes config set model.key_env LITELLM_MASTER_KEY
Select-String -Path $HOME\.config\litellm\.env -Pattern '^LITELLM_MASTER_KEY=' | ForEach-Object { $_.Line } | Add-Content $env:LOCALAPPDATA\hermes\.env
hermes
```

</OsBlock>

То же интерактивно: `hermes model` → «Custom endpoint». В России вместо `fast-pool` поставь `balanced` (GigaChat). Hermes требует у модели контекст от 64K токенов — с меньшим он не стартует.

Любой другой OpenAI-совместимый агент подключается теми же тремя значениями: адрес `http://127.0.0.1:4000/v1`, ключ — `LITELLM_MASTER_KEY`, модель — `fast-pool`.

Готово. Полноценный agentic workflow без Anthropic, без OpenAI, без VPN.
