## Как устроен канал

Сообщение идёт из мессенджера до сессии агента на твоём компьютере и обратно:

```
ты в мессенджере → бот → плагин-канал → запущенная сессия агента → твои файлы
                                                  ↓
ты в мессенджере ← бот ← ответ агента ←───────────┘
```

Три важных свойства:

- **Работа идёт у тебя.** Агент отвечает из сессии на твоём компьютере и работает с настоящими файлами. Облако мессенджера только передаёт текст.
- **Сессия должна быть открыта.** Нет запущенной сессии — некому ответить. Для постоянной связи агента держат в отдельном окне терминала или в фоновом процессе.
- **Бот — это адрес.** Каждый, кто знает имя бота, может ему написать. Поэтому нужен список разрешённых отправителей.

## Каналы в Claude Code

У Claude Code для этого есть **Channels** — [официальная документация](https://code.claude.com/docs/en/channels). Сейчас это research preview: набор каналов и синтаксис команд могут меняться. Поэтому шаги ниже — пересказ документации, а первоисточник всегда главнее.

**Требования:**

- Вход в Claude Code через аккаунт claude.ai или ключ Anthropic Console. Через Amazon Bedrock, Google Cloud's Agent Platform и Microsoft Foundry каналы недоступны.
- Pro и Max без организации — работает сразу. В Team и Enterprise каналы сначала включает администратор с ролью Owner.
- [Bun](https://bun.sh): плагины каналов работают на нём. Проверка — `bun --version`.
- Флага `--channels` нет в `claude --help`, пока идёт preview, но он работает.

В preview входят Telegram, Discord и iMessage (iMessage — только на macOS). Каждый канал — плагин из официального маркетплейса. Когда установщик спросит про scope, выбирай user scope: так плагин будет доступен во всех твоих проектах.

**Репетиция без внешних сервисов — fakechat.** Это демо-канал: чат в браузере на твоём компьютере, без ботов и токенов.

```
/plugin install fakechat@claude-plugins-official
```

Затем выйди из Claude Code и запусти его заново с каналом:

```bash
claude --channels plugin:fakechat@claude-plugins-official
```

При старте Claude Code покажет строку: сообщения от `plugin:fakechat@claude-plugins-official` попадают прямо в эту сессию.

Открой `http://localhost:8787` и отправь сообщение. В терминале оно появится строкой вида `← fakechat · web: …`. Агент ответит вызовом инструмента `reply`: в терминале видно сам вызов, а текст ответа — только в браузере. Если перед первым ответом Claude Code спросит разрешение — одобри.

**Telegram — по шагам документации:**

1. В Telegram открой [@BotFather](https://t.me/BotFather), отправь `/newbot`, получи токен бота.
2. В Claude Code: `/plugin install telegram@claude-plugins-official`. Если установщик пишет «Run /reload-plugins to activate», выполни `/reload-plugins`.
3. Сохрани токен: `/telegram:configure <токен>`. Он ляжет в `~/.claude/channels/telegram/.env` — вне проекта и вне git. Другой вариант — задать переменную окружения `TELEGRAM_BOT_TOKEN` перед запуском Claude Code.
4. Перезапусти: `claude --channels plugin:telegram@claude-plugins-official`.
5. Напиши боту — он пришлёт код привязки. В Claude Code: `/telegram:access pair <код>`.
6. Закрой дверь для остальных: `/telegram:access policy allowlist`.

После шестого шага сообщения от чужих аккаунтов молча отбрасываются. Этот шаг не пропускай.

## Если не заработало

Первый запуск чаще всего спотыкается о маркетплейс, незапущенный канал, занятый порт или требования:

- **«Marketplace "claude-plugins-official" not found».** Добавь маркетплейс: `/plugin marketplace add anthropics/claude-plugins-official` — и повтори установку.
- **Бот не присылает код.** Проверь, что Claude Code запущен с `--channels`: без запущенного канала бот молчит.
- **Порт 8787 занят после аварийного выхода.** Скорее всего, висит прошлый сервер канала — процесс Bun. Найди процесс, который держит порт: в Windows — через Диспетчер задач или Монитор ресурсов, в macOS и Linux — `lsof -i :8787`. Закрой именно его и запусти заново.
- **Нет ни строки о канале при старте, ни сообщений.** Сверь требования выше: способ входа, тариф, Bun.

## Почта и другие агенты

**Почта** обычно подключается иначе: через MCP-сервер почтового сервиса (модуль [07](/lessons/07-tools/)). Агент читает письма, когда ты его просишь, а не получает их сам.

Учти: написать тебе письмо может кто угодно в мире. Список разрешённых отправителей здесь не встроен.

**Другие агенты** — Hermes, OpenClaw и похожие — умеют жить в мессенджерах через свои шлюзы. Схема та же: бот, разрешённые отправители, работа на твоей машине. Команды смотри в их документации.

## Когда ты не у терминала

Если агенту нужно твоё разрешение на действие, сессия ждёт ответа. Канал может переслать такой промпт в мессенджер. Тогда одобрить или отклонить действие агента сможет любой из списка разрешённых — ещё одна причина держать там только себя (юнит 4, правило 5).

Документация упоминает и режим, который пропускает такие вопросы. Для агента, до которого можно достучаться снаружи, мы его не включаем — почему, разберём в юните 4.
