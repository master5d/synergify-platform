## Схема: утренний разбор ссылок

```
Trigger:   расписание, каждый день в 8:00
Вход:      inbox.txt — ссылки, которые ты накидал за день
Condition: ссылка уже есть в done.txt → пропустить
Action:    агент читает страницу и пишет разбор по prompt.md
Выход:     digest-ГГГГ-ММ-ДД.md, ссылка → done.txt
```

Ты дописываешь ссылку в `inbox.txt` одной строкой. Утром тебя ждёт готовый файл с разбором.

## Condition «дубли» — это идемпотентность

Скрипт будет запускаться каждый день по одному и тому же `inbox.txt`. Без условия он каждое утро заново разберёт все старые ссылки. Это ровно тот случай из u1: дубли и упор в лимиты.

`done.txt` — память pipeline о том, что уже сделано. Повторный запуск не меняет результат и не тратит лимиты. У такого свойства есть имя: **идемпотентность**.

В модуле 08 ты увидишь его в настоящем production-pipeline. Там письмо после обработки получает метку, чтобы его не схватили второй раз ([08, «Оркестрация: Gmail-агент как кейс»](/lessons/08-agent-engineering/u3-orchestration/)). У тебя та же идея, только вместо метки — строка в файле.

Второе правило оттуда же: ссылка попадает в `done.txt` **только после успешного разбора**. Упал прогон — ссылка останется в очереди, и завтра скрипт попробует снова.

## Почему не Hook

Hooks из модуля 07 срабатывают на события агента: агент записал файл, закончил ответ. Сам по себе, по часам, hook не проснётся. Для расписания нужен планировщик операционной системы: `cron` на macOS и Linux, «Планировщик заданий» в Windows. Он запускает обычный скрипт, а скрипт вызывает агента в неинтерактивном режиме.

Весь детерминированный код здесь — проверка дублей, даты, файлы — делается скриптом. Модель вызывается только там, где нужен смысл. Это тот же принцип, что в модуле 08: AI в двух узлах из девяти.

<Phase type="practice">

Пример ниже — для Claude Code (команда `claude -p`, [документация](https://code.claude.com/docs/en/headless)). В другом стеке замени одну строку вызова агента на неинтерактивный режим своего агента (модуль 03). Остальной скрипт не меняется.

**Шаг 1. Папка и промпт.** Создай папку `~/my-experiments/pipeline/`. Если твоя `my-experiments` лежит в другом месте, поправь путь и в строках расписания ниже. Скопируй туда свой промпт из u3 как `prompt.md`. Строку «URL для анализа: [вставь ссылку]» замени на «URL для анализа — в конце сообщения».

**Шаг 2. Скрипт.** Сохрани в ту же папку `run.sh`:

```bash
#!/usr/bin/env bash
# run.sh — утренний разбор ссылок из inbox.txt
cd "$(dirname "$0")" || exit 1
exec >> run.log 2>&1
echo "== $(date)"
touch inbox.txt done.txt
out="digest-$(date +%F).md"
while read -r url; do
  url="${url%$'\r'}"
  [ -z "$url" ] && continue
  grep -qxF "$url" done.txt && continue
  if claude -p "$(cat prompt.md)
URL: $url" --allowedTools "WebFetch" < /dev/null > last.md; then
    cat last.md >> "$out"
    echo "$url" >> done.txt
  else
    echo "FAIL: $url (повторю в следующий раз)"
  fi
done < inbox.txt
```

Что здесь что:
- `grep -qxF … && continue` — condition «дубли»: уже разобранную ссылку пропускаем.
- `echo "$url" >> done.txt` стоит только в ветке успеха: упавшая ссылка не теряется.
- `< /dev/null` обязателен: без него агент прочитает остаток `inbox.txt` как свой ввод.
- `--allowedTools "WebFetch"` разрешает агенту читать страницы без вопроса — спросить тебя ночью некому.
- `${url%$'\r'}` срезает невидимый символ конца строки, если `inbox.txt` правили в Блокноте.

**Шаг 3. Ручной прогон.** Положи в `inbox.txt` две ссылки, одну из них дважды. Запусти `bash run.sh` в папке pipeline. В `digest-….md` должно быть два разбора, а не три. Запусти ещё раз: новых разборов быть не должно. Это и есть проверка идемпотентности.

**Шаг 4. Расписание.** Сначала поставь запуск на ближайшие 2–3 минуты, убедись, что он сработал, и только потом переставь на 8:00.

macOS / Linux: `crontab -e`, добавь строку (пример — каждый день в 8:00):

```
0 8 * * * /bin/bash -l "$HOME/my-experiments/pipeline/run.sh"
```

Формат строки: минута, час, день месяца, месяц, день недели. Подробнее — `man 5 crontab`.

Windows (нужен Git Bash — он уже стоит вместе с Claude Code). В PowerShell, подставив своё имя пользователя:

```
schtasks /Create /SC DAILY /ST 08:00 /TN "my-pipeline" /TR '"C:\Program Files\Git\bin\bash.exe" -l C:/Users/ИМЯ/my-experiments/pipeline/run.sh'
schtasks /Run /TN "my-pipeline"
```

Вторая команда запускает задачу сразу, для проверки. В PowerShell используй одинарные кавычки снаружи; в cmd — двойные с экранированием. Параметры — в [документации schtasks](https://learn.microsoft.com/windows-server/administration/windows-commands/schtasks-create).

**Шаг 5. Проверка.** Открой `run.log`. Если там `claude: command not found` — планировщик не видит твой PATH. Выполни `command -v claude` и впиши в `run.sh` полный путь вместо `claude`. Учти: спящий ноутбук пропускает запуск, выбирай время, когда компьютер включён.

**Другие пути к тому же расписанию.**
У меня n8n стоял в Docker на арендованном сервере, но рабочих workflow там не было.
При самопроверке я обнаружил, что его веб-интерфейс был открыт в интернет напрямую: Docker публиковал `0.0.0.0:5678` мимо firewall хоста.
Я удалил n8n целиком.
Правило, которое из этого вывел: сервис на сервере должен слушать `127.0.0.1` или частную сеть между моими устройствами.
Наружу — только через Cloudflare или не наружу вовсе.
Это объясняет мой выбор скриптов в git: их проще читать, тестировать и откатывать как обычный код.
У конструктора отдельно нужно следить за портом, базой кредов и версией.
Но это не правило курса: если ты не пишешь код, n8n или Make.com могут подойти — проверь, какой порт открывает сервис, и держи его закрытым.
- В облаке, если у тебя платная подписка Claude: `/schedule` создаёт routine, которая работает, даже когда ноутбук закрыт ([документация](https://code.claude.com/docs/en/routines)). Routine работает с GitHub-репозиторием, а не с твоей локальной папкой, так что `inbox.txt` и `done.txt` придётся держать в репо.

Сохрани в `my-experiments/u5-schedule.md`: строку расписания, первый `digest-….md` и одну фразу — что pipeline сделал без тебя.

В модуле 07 этот pipeline вырастет. Промпт станет Skill, а в конце появится уведомление.
