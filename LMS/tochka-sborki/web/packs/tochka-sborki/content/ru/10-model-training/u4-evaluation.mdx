## Holdout: отложи до начала

Главное правило оценки: **часть примеров откладывается до обучения и не показывается модели**. Это **holdout** — отложенная выборка.

Обычно данные делят на три части:

- **train** — на них модель учится;
- **validation** — на них подбираешь настройки по ходу;
- **test** — смотришь один раз в конце.

Если ты правил данные, глядя на ошибки на test, он превратился в validation. Для честной оценки нужен новый.

## Переобучение

**Переобучение** (overfitting) — модель подстраивается под обучающие примеры так плотно, что хуже работает на новых. Сигнал в логах: ошибка (loss) на train продолжает падать, а на validation перестаёт падать или растёт.

Что помогает: больше разнообразных примеров, меньше эпох (проходов по данным), ранняя остановка по validation.

У дообучения есть и обратная сторона — **катастрофическое забывание** (catastrophic forgetting). Модель выучила твой формат и разучилась тому, что умела раньше. Поэтому проверяй и старые умения, а не только новое.

## Бенчмарк против своей задачи

Публичные **бенчмарки** меряют общие навыки: знания, рассуждение, код. Они полезны, чтобы сравнивать модели между собой.

Но у них два ограничения для тебя:

1. Бенчмарк не знает твою задачу. Рост на нём не обещает рост на твоих обращениях.
2. Тексты популярных бенчмарков могли попасть в обучающие данные моделей. Тогда высокий балл отчасти меряет память.

Поэтому для своей задачи собирай **свой набор проверки** — из того же holdout.

## Как понять, что дообучение помогло

1. **Критерии до прогона.** Реши заранее, что считается хорошим ответом: формат соблюдён, поле извлечено верно, тон подходит.
2. **Один и тот же набор** holdout прогони через модель «до» и «после».
3. **Сравни по критериям**, а не по впечатлению. Если можешь — смотри ответы, не зная, какая модель их дала.
4. **Проверь, что не сломалось:** пара вопросов на общие умения.
5. **Сравни с дешёвой альтернативой:** та же исходная модель с хорошим промптом из модуля 04. Если разница мала — дообучение не окупилось.

Размер проверочного набора — вопрос задачи. Для первой прикидки хватит нескольких десятков примеров. Это оценка порядка, а не норма.

```
Задача: [...]
Сколько примеров всего: [...]
  → train: [...]  validation: [...]  test (holdout): [...]
Как отложил holdout: [случайно / по времени / по источнику — почему так]

Критерии хорошего ответа (до прогона):
1. [...]
2. [...]
3. [...]

Дешёвая альтернатива для сравнения: [промпт из модуля 04 / контекст из модуля 05]
Что проверю на забывание: [2–3 вопроса на общие умения]
```

Сохрани в `my-experiments/u4-eval-plan.md`.

Этот план — половина практики юнита 5. Без него любой результат дообучения будет впечатлением, а не измерением.
