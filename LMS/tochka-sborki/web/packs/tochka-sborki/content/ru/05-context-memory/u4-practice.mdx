Не смотри на них как на «документацию». Представь это как **передачу вахты новому смотрителю маяка**: уходящий оставляет не просто инструкцию, а всё, что нужно, чтобы свет не погас. Особенности механизма, ритм волн в этом заливе, где скрипит дверь в шторм.

Прокрути в голове: что в твоих файлах уже передаёт «живое знание» маяка? Что ты пока держишь только у себя в голове, но однажды должен будет передать?

Хорошая система памяти — это не разовая настройка. Это живая система.

Не думай об этом как о «правилах». Представь джазового музыканта, который **передаёт тему (head) новому составу**: не ноты на бумаге, а живое ощущение. Как держать паузу, где можно импровизировать, а где структура должна стоять твёрдо.

Поймай момент: когда Claude последний раз делал что-то «не в том ключе» — это был сигнал. Что ты добавил бы в партитуру, чтобы следующий «музыкант» сразу почувствовал нужный ритм?

</Phase>

## Когда обновлять что

| Событие | Где обновить |
|---------|-------------|
| Изменилась архитектура | AGENTS.md, разделы о проекте |
| Добавили новый стек | AGENTS.md, «Стек» |
| Завершена задача | TODO.md |
| Сессия закончилась | STATE.md: где остановились, что дальше |
| Агент сделал ошибку, которую ты исправил | AGENTS.md, «Правила» |
| Уточнение в середине сессии, которое агент должен учитывать дальше | Обычное сообщение в сессии (или правило в AGENTS.md, если оно нужно и в следующих сессиях) |

`/btw` для этого не подходит: это побочный вопрос о текущей сессии, и в историю разговора он не попадает.

## Техники для длинных сессий

### Сжатие контекста

В начале новой сессии или когда контекст заполнился:

```
Кратко резюмируй что было сделано и в каком состоянии проект.
Используй формат: ✅ Сделано / ❌ Осталось / ⚠️ Проблемы
```

### Приоритизация информации

```markdown
## ⚠️ КРИТИЧНО (всегда держи в фокусе)
[Самое важное для текущей задачи]

## 📋 КОНТЕКСТ (полезно знать)
[Дополнительные детали]
```

### Параллельные агенты для больших задач

Для независимых подзадач можно запустить несколько агентов:

```
Агент 1: Найди все баги в модуле Auth
Агент 2: Напиши тесты для модуля Payment
Агент 3: Обнови документацию API

Потом объедини результаты.
```
