## 🖥️ CLI: запуск и флаги

```bash
claude                          # Интерактивный режим
claude "запрос"                 # Запуск с начальным запросом
claude -p 'запрос'              # Pipe-режим: ответ в stdout и выход
claude -c                       # Продолжить последнюю сессию
claude -r <id>                  # Возобновить сессию по ID
claude update                   # Обновить Claude Code

# Полезные флаги
--model <модель>                # Указать модель при запуске
--permission-mode plan          # Запустить только в режиме чтения
--worktree / -w                 # Изолированный git worktree
--autocompact <auto|tokens>      # Режим авто-сжатия контекста; -n = --name
--add-dir <путь>                # Добавить папку в контекст
--output-format json|text|stream-json
--max-budget-usd <N>            # Бюджет сессии в долларах
--bare                          # Минимальный режим: без hooks, LSP, синхронизации плагинов, auto-memory

# Pipe-режим — удобно для скриптов:
cat error.log | claude -p 'объясни ошибку'
```

## 📋 Управление сессией

```bash
/clear                  # Полная очистка контекста
/compact [тема]         # Сжать контекст, сохранив суть
/context                # Показать заполненность контекста
/resume                 # Список последних сессий для возобновления
/rename <название>      # Переименовать сессию (удобно при /resume)
/branch                 # Создать ответвление сессии
/cost                   # Стоимость текущей сессии ($, токены)
/diff                   # Все изменения файлов за сессию
/copy                   # Скопировать последний ответ
/export                 # Экспорт диалога в Markdown
```

**Дерево решений /clear vs /compact:**

| Ситуация | Команда |
| --- | --- |
| Контекст полон (&gt;80%) или задача сменилась | `/compact` |
| Контекст &lt;70% и задача та же | Продолжай |

> 💡 CLAUDE.md (а с ним и подключённый `@AGENTS.md`) **перезагружается автоматически** после /compact и auto-compact — инструкции не теряются.

## ⚙️ Настройки

```bash
/config                         # Открыть settings.json в редакторе
/model <модель>                 # Переключить модель в сессии
/fast                           # Переключить на Haiku (быстро/дёшево)
/effort low|medium|high         # Глубина анализа
/permissions                    # Просмотр и настройка разрешений
/vim                            # Включить vim-режим редактирования
/theme                          # Сменить цветовую тему
```

**Режимы разрешений:**

| Режим | Поведение |
| --- | --- |
| `default` | Значение в settings.json; в CLI это `manual` |
| `auto` | Автоматически принимает безопасные действия |
| `acceptEdits` | Автопринимает правки файлов, спрашивает bash |
| `manual` | Спрашивает перед действиями |
| `plan` | Только чтение, никаких изменений |
| `dontAsk` | Не спрашивает для разрешённых инструментов |
| `bypassPermissions` | ⚠️ Полный доступ без подтверждений |

## 🌀 Ultrathink

Активировать глубокое мышление — слова-триггеры в промпте:

```
think → think hard → think harder → ultrathink
```

Или клавиша `Alt+T`. Полезно для: архитектурных решений, сложных багов, неоднозначных ТЗ.

**Паттерн Plan → Normal → Auto:**
```
1. Plan mode   → только разведка, без изменений
2. Normal mode → реализация с подтверждением
3. Auto-accept → рутина без подтверждений (Shift+Tab)
```

## 🔁 Процесс: план, проверка, ревью

- **План по этапам, у каждого этапа — своя проверка.** Не «сделай всё», а «этап 1 → тест → этап 2 → тест». Сломалось — видно где.
- **Ревью свежим взглядом.** Готовую работу отдай на проверку в **новой** сессии или другой модели (Claude ↔ Codex). Автор кода не видит своих ошибок; новый контекст их находит.
- **Сначала пусть расспросит тебя.** Перед работой попроси агента взять у тебя интервью: в Claude Code это инструмент `AskUserQuestion`, у любого другого — «задай мне 5 вопросов, прежде чем начать». Дешевле ответить на вопросы, чем переделывать.
- **субагент — под один Skill.** Не «универсальный QA-инженер», а «проверяет миграции БД» или «читает логи Chrome». Узкая роль с конкретным инструментом работает; широкая — размазывается.
- **Набор своих примеров.** 10–20 случаев с ожидаемым результатом — прогоняй после каждой правки промпта или кода.
- **Сначала данные, потом интерфейс.** Убедись, что pipeline собирает правильные данные, и только потом строй экран над ними: красивый интерфейс над пустой базой — самая дорогая ошибка новичка.
- **Проси пресеты.** Всё, что ты запускаешь чаще двух раз, — попроси агента вынести в типовую конфигурацию, а параметр, который может измениться, — в настройки, а не в код.
- **Проект дольше одного вечера** — возьми готовый процесс: Superpowers или Spec Kit (ссылки в «Материалах»).

## 📄 Обязательные файлы проекта

### AGENTS.md

Один файл контекста и правил проекта для любого агента: Codex, Cursor, Copilot, Antigravity, Hermes читают его сами.

**Где разместить:**
- `./AGENTS.md` — проект (коммитится в git)
- `./CLAUDE.md` — одна строка `@AGENTS.md`: так его читает Claude Code
- `~/.claude/CLAUDE.md` — личный (все проекты, только Claude Code)

**Лимит:** ~200 строк (важно для контекста)

**Минимальная структура:**
```markdown
# AGENTS.md
## Моя роль
## Проект
## Стек
## Как запустить
## Правила
## Чего избегать
```

`/init` в Claude Code генерирует CLAUDE.md из существующего проекта. Перенеси полезное в AGENTS.md, а в CLAUDE.md оставь `@AGENTS.md`.

### TODO.md
```markdown
# Tasks
## 🔴 КРИТИЧНО
## 🟡 ВАЖНО
## 🟢 ПОЗЖЕ
## ⏸️ БЛОКИРОВАНА
## ✅ ЗАВЕРШЕНО
```

### STATE.md
```markdown
# Состояние проекта
## Где мы сейчас
## Что сделано
## Что мешает
## Следующий шаг
```

## ⚠️ Типичные ошибки

| Ошибка | Решение |
| --- | --- |
| Контекст переполнен | Дай только релевантные файлы |
| Агент спрашивает всё | Добавь информацию в AGENTS.md |
| Результат неправильный | Уточни, что именно не так, итерируй |
| Дистракторы | Убери лишние файлы из контекста |
| "Lost in the Middle" | Важное в начало или конец, не в середину |

## 🔢 Токены

> 📖 Что такое токен, контекстное окно, температура, промпт и контекст, агент — простыми словами в юните [«Азбука: шесть слов до старта»](/lessons/00-kickstart/u0-azbuka/).

```
1 токен ≈ 4 символа
1000 токен ≈ 750 слов

Стоимость:
- Input token = дешевле
- Output token = дороже (в 2-3 раза)

Оптимизация:
- Сжимай контекст
- Убирай лишнее
- Структурируй данные
```

## 🖥️ Различия Mac / Windows

Где команды реально расходятся (остальное — одинаково):

| Что нужно | macOS / Linux | Windows (PowerShell) |
| --- | --- | --- |
| Создать пустой файл | `touch file.md` | `ni file.md -ItemType File` |
| Создать несколько | `touch a.md b.md c.md` | `ni a.md, b.md, c.md -ItemType File` |
| Цепочка команд | `cmd1 && cmd2` | `cmd1; cmd2` (или `&&` в pwsh 7+) |
| Pipe файла в Claude | `cat err.log \| claude -p ...` | `Get-Content err.log \| claude -p ...` |
| Переменная окружения | `export KEY=value` | `$env:KEY = "value"` |
| Hotkey: Plan-режим | `Option+P` | `Alt+P` |
| Hotkey: ultrathink | `Option+T` | `Alt+T` |
| Вставка | `Cmd+V` | `Ctrl+V` |
| Путь к домашнему `.claude` | `~/.claude/` | `$env:USERPROFILE\.claude\` |

</OsBlock>

```bash

/doctor             # Диагностика установки

/cost               # Стоимость сессии
/btw                # Добавить контекст не прерывая
/plan               # Режим планирования
```

## 🔭 Где подсмотреть реализации

Когда нужен не совет, а рабочий пример: два открытых каталога приложений на LLM — от простых ботов до мультиагентных систем. Оба на английском, оба живые (коммиты идут еженедельно), код можно читать и забирать.

```
awesome-llm-apps      github.com/Shubhamsaboo/awesome-llm-apps
                      Apache-2.0 · RAG, ИИ-агенты, мультиагентные команды, MCP, голосовые агенты

awesome-ai-apps       github.com/Arindam200/awesome-ai-apps
                      MIT · практические примеры, руководства и рецепты: от чат-бота до агента
```

Смотри там не «что скопировать», а как чужие решения устроены: где границы агента, что вынесено в инструменты, чем меряется результат.
