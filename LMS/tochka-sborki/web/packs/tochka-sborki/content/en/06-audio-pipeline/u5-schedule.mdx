<Phase type="concept">

## The shape: a morning link digest

```
Trigger:   schedule, every day at 8:00
Input:     inbox.txt — links you dropped in during the day
Condition: link already in done.txt → skip it
Action:    the agent reads the page and writes a breakdown per prompt.md
Output:    digest-YYYY-MM-DD.md, the link → done.txt
```

You add a link to `inbox.txt` as one line. In the morning a finished file is waiting for you.

## The "duplicates" condition is idempotency

The script will run every day over the same `inbox.txt`. Without a condition it would re-process every old link each morning. That is exactly the u1 case: duplicates and hitting rate limits.

`done.txt` is the pipeline's memory of what is already done. A repeat run changes nothing and spends no quota. This property has a name: **idempotency**.

In module 08 you will see it in a real production pipeline. There an email gets a label after processing, so it is never picked up twice ([08, "Orchestration: the Gmail agent as a case"](/en/lessons/08-agent-engineering/u3-orchestration/)). Your idea is the same, only a line in a file replaces the label.

A second rule comes from the same place: a link goes into `done.txt` **only after a successful run**. If a run fails, the link stays in the queue and the script retries tomorrow.

## Why not a Hook

The Hooks from module 07 fire on agent events: the agent wrote a file, finished a reply. A hook never wakes up by the clock on its own. A schedule needs the operating system's scheduler: `cron` on macOS and Linux, Task Scheduler on Windows. It starts an ordinary script, and the script calls the agent in non-interactive mode.

All the deterministic work here — the duplicate check, dates, files — is done by the script. The model is called only where meaning is needed. It is the same principle as in module 08: AI in two steps out of seven.

<Phase type="practice">

The example below is for Claude Code (the `claude -p` command, [documentation](https://code.claude.com/docs/en/headless)). On another stack, swap the one line that calls the agent for your agent's non-interactive mode (module 03). The rest of the script stays the same.

**Step 1. Folder and prompt.** Create the folder `~/my-experiments/pipeline/`. If your `my-experiments` lives elsewhere, fix the path in the schedule lines below too. Copy your prompt from u3 into it as `prompt.md`. Replace the line "URL to analyze: [paste link]" with "URL to analyze: at the end of this message".

**Step 2. The script.** Save `run.sh` into the same folder:

```bash
#!/usr/bin/env bash
# run.sh — morning digest of the links in inbox.txt
cd "$(dirname "$0")" || exit 1
exec >> run.log 2>&1
echo "== $(date)"
touch inbox.txt done.txt
out="digest-$(date +%F).md"
while read -r url; do
  url="${url%$'\r'}"
  [ -z "$url" ] && continue
  grep -qxF "$url" done.txt && continue
  if claude -p "$(cat prompt.md)
URL: $url" --allowedTools "WebFetch" < /dev/null > last.md; then
    cat last.md >> "$out"
    echo "$url" >> done.txt
  else
    echo "FAIL: $url (will retry next time)"
  fi
done < inbox.txt
```

What each part does:
- `grep -qxF … && continue` is the "duplicates" condition: an already processed link is skipped.
- `echo "$url" >> done.txt` sits only in the success branch: a failed link is not lost.
- `< /dev/null` is required: without it the agent reads the rest of `inbox.txt` as its own input.
- `--allowedTools "WebFetch"` lets the agent read pages without asking — nobody is there to answer at night.
- `${url%$'\r'}` strips an invisible line-ending character if `inbox.txt` was edited in Notepad.

**Step 3. A manual run.** Put two links into `inbox.txt`, one of them twice. Run `bash run.sh` in the pipeline folder. `digest-….md` should hold two breakdowns, not three. Run it again: there should be no new breakdowns. That is your idempotency check.

**Step 4. The schedule.** First schedule a run 2–3 minutes from now, make sure it fired, and only then move it to 8:00.

macOS / Linux: run `crontab -e` and add a line (example: every day at 8:00):

```
0 8 * * * /bin/bash -l "$HOME/my-experiments/pipeline/run.sh"
```

The line format is: minute, hour, day of month, month, day of week. More in `man 5 crontab`.

Windows (needs Git Bash — it is installed with Git for Windows; if `bash --version` does not respond in PowerShell, install it). In PowerShell, with your own user name:

```
schtasks /Create /SC DAILY /ST 08:00 /TN "my-pipeline" /TR '"C:\Program Files\Git\bin\bash.exe" -l C:/Users/NAME/my-experiments/pipeline/run.sh'
schtasks /Run /TN "my-pipeline"
```

The second command runs the task right away, as a test. In PowerShell, use single quotes around the `/TR` value; in cmd, use double quotes with escaping. The parameters are in the [schtasks documentation](https://learn.microsoft.com/windows-server/administration/windows-commands/schtasks-create).

**Step 5. Check it.** Open `run.log`. If it says `claude: command not found`, the scheduler cannot see your PATH. Run `command -v claude` and put the full path into `run.sh` instead of `claude`. Keep in mind: a sleeping laptop skips the run, so pick a time when the computer is on.

**Other routes to the same schedule.**
- No-code (n8n/Make.com): the author tried n8n, then removed it after a self-scan found a Docker port exposed to the internet. If you choose this route, check the port, credential database, and version; keep it behind Cloudflare or on a private network. It is an option if you do not write code.
- In the cloud, if you have a paid Claude plan: `/schedule` creates a routine that runs even when your laptop is closed ([documentation](https://code.claude.com/docs/en/routines)). A routine works with a GitHub repository, not your local folder, so `inbox.txt` and `done.txt` have to live in the repo.

Save to `my-experiments/u5-schedule.md`: your schedule line, your first `digest-….md`, and one sentence on what the pipeline did without you.
