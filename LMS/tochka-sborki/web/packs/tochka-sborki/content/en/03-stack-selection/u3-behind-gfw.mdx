## Access map

The Behind-Firewall stack (earlier in the course, Behind-GFW, after China's Great Firewall) fits anywhere AI services are closed by state filtering or by the vendors themselves. Below are two maps: China and Russia.

### China

Without a VPN in mainland China, Claude, OpenAI, most AI IDEs, AI Studio, and Hugging Face are unavailable; GitHub and npm need mirrors. Cerebras must be checked locally, while DeepSeek, Qwen, and local models are available supports. In 2026, Qwen, DeepSeek, and GLM are strong open models; local providers often accept WeChat Pay and Alipay.

### Russia

Claude, OpenAI, and Gemini (AI Studio) are closed to Russia by the companies themselves: they don't serve users in Russia, and a VPN doesn't change that — signing in through a VPN breaks their terms, and accounts get banned. Other foreign providers don't accept Russian cards either. DeepSeek opens from Russia, but there's no official way to top up its API balance with a Russian card. The available supports are Sber's GigaChat (there's a free tier for individuals; check the terms at sign-up), YandexGPT in Yandex Cloud (paid with a Russian card), and local models. There's no official data on Cerebras access from Russia — check it yourself.

### How to recognise a firewall by its symptoms

A firewall gives itself away like this: the TCP connection to the server is established, but the TLS handshake times out, and it happens on several domains of the same service at once. Switching clients or disabling IPv6 doesn't help: the problem isn't your computer but a filter on the provider's side (in Russia, the TSPU boxes).

Since June 2025, Russian ISPs have also been throttling connections to sites behind Cloudflare: often only the first 16 KB get through, and the page loads halfway. This course also runs through Cloudflare — if a unit opened only partly, that's the same cause.

If the course doesn't load fully, try the mirror on GitHub: [master5d.github.io/ts-gitbook](https://master5d.github.io/ts-gitbook/) — the same units, read-only, without sign-in or the certificate.

> ⚠️ This unit doesn't teach how to fix a VPN: in Russia, promoting ways to bypass blocking has been banned since March 2024, and in China VPNs are a grey zone. The stack below doesn't need a VPN.

## ⚡ Quick install of the Behind-Firewall stack (one line)

One command installs the LiteLLM proxy and the Hermes agent (with the official Nous Research installer), writes a ready config (Cerebras + Gemini Flash), and connects Hermes to the model gateway. Gemini doesn't work in China — after install, replace it with a Chinese provider (step 2); for Russia the installer has its own mode (below). The step-by-step breakdown is below if you want to understand what happens.

<OsToggle />

<OsBlock os="mac">

```bash
curl -fsSL https://ai.synergify.com/install-gfw.sh | bash
```

</OsBlock>

<OsBlock os="windows">

```powershell
irm https://ai.synergify.com/install-gfw.ps1 | iex
```

</OsBlock>

> 💡 On Linux, use the same command as Mac (`curl … | bash`).

**In Russia,** run the installer in Russia mode — it writes GigaChat instead of Gemini right away (step 2b) and tells you which key to add:

<OsBlock os="mac">

```bash
curl -fsSL https://ai.synergify.com/install-gfw.sh | bash -s -- --ru
```

</OsBlock>

<OsBlock os="windows">

```powershell
$env:GFW_REGION = 'ru'; irm https://ai.synergify.com/install-gfw.ps1 | iex
```

</OsBlock>

> ⚠️ This, too, runs someone else's script in one line. If you want to read it first, do as in module 02: save it to a file, open it, then run it.

After install: add your provider keys to `~/.config/litellm/.env`, run `start.sh`/`start.ps1`, and in another terminal run `hermes`. The installer has already written the model gateway key `LITELLM_MASTER_KEY` to `.env` (recent LiteLLM won't start without it) and handed it to Hermes. The Hermes installer needs access to `hermes-agent.nousresearch.com` and GitHub; if it didn't get through, the model gateway still works — check it with the request from the practice, and install Hermes per step 5 when the network allows.

## "Behind-Firewall" architecture

```
┌─────────────────────────────────────────────────────────┐
│  Agent: Hermes (or any OpenAI-compatible one)           │
├─────────────────────────────────────────────────────────┤
│  Router: LiteLLM (localhost:4000)                       │
│  ┌────────────────────────────────────────────────────┐ │
│  │ fast-path:  Cerebras gpt-oss-120b                  │ │
│  │ balanced:   current Gemini Flash model (check console name) │ │
│  │ local:      DeepSeek/Qwen (CN), GigaChat (RU)      │ │
│  │ floor:      local llama-server (Qwen3-Coder-30B)   │ │
│  └────────────────────────────────────────────────────┘ │
└─────────────────────────────────────────────────────────┘
```

## Step 1: Cerebras (main free tier)

1. Go to [cerebras.ai/cloud-inference](https://cerebras.ai/cloud-inference) — there's no official word on access from China — check it yourself
2. Sign up with email. Trial terms change: right now the bonus credits require linking a card
3. Check the trial limits (currently around 1M tokens a day) on the Rate Limits page of the Cerebras docs — they change often
4. Grab the API key → save in `~/.config/litellm/.env` (the same file the quick install uses):

```bash
# ~/.config/litellm/.env
CEREBRAS_API_KEY=csk-xxxxx
```

## Step 2: Google Gemini Flash (backup for longer tasks)

1. `aistudio.google.com` is officially unavailable from mainland China and from Russia. If you're in China, put a Chinese provider in this role (DeepSeek API or Qwen API). If you're in Russia, go to step 2b. If not, get a key in AI Studio and add it to the same `.env`: `GOOGLE_API_KEY=...`
2. Gemini's free limits change — check them in your own AI Studio, not by numbers in a unit

## Step 2b: GigaChat instead of Gemini (Russia)

1. Sign up for the GigaChat API at [developers.sber.ru](https://developers.sber.ru/docs/ru/gigachat/tariffs/individual-tariffs) and create a project. Check the free tier for individuals and its limits there too: the terms change
2. Copy the project's authorization key (that's `Client ID:Client Secret` in base64) and add it to the same `.env`:

```bash
# ~/.config/litellm/.env
GIGACHAT_CREDENTIALS=authorization-key
```

3. In the step 3 config, put GigaChat in the `balanced` role instead of Gemini (the installer in Russia mode has already written this block):

```yaml
  - model_name: balanced
    litellm_params:
      model: gigachat/GigaChat-2-Lite   # check model names in your GigaChat dashboard
      api_key: os.environ/GIGACHAT_CREDENTIALS
      ssl_verify: false
```

> ⚠️ `ssl_verify: false` is what the LiteLLM docs advise: GigaChat's certificate is issued by a Russian certificate authority that isn't in the standard trusted set. The line turns certificate checking off — keep it only in the GigaChat block. The `gigachat/` provider exists in recent LiteLLM versions: if it's missing, update with `pip install -U 'litellm[proxy]'`.

> 💡 The course author hasn't walked this path from Russia (October 2026): the config comes from the LiteLLM docs. If something doesn't match, send feedback and we'll fix it.

## Step 3: LiteLLM model gateway

"One endpoint for all providers". Installed locally:

<OsToggle label="Commands for:" />

<OsBlock os="mac">

```bash
pip install 'litellm[proxy]'
mkdir -p ~/.config/litellm
```

</OsBlock>

<OsBlock os="windows">

```powershell
pip install 'litellm[proxy]'
New-Item -ItemType Directory $HOME\.config\litellm -Force
```

</OsBlock>

Minimal config in `~/.config/litellm/config.yaml`:

```yaml
model_list:
  - model_name: fast-pool
    litellm_params:
      model: cerebras/gpt-oss-120b      # check against the current Cerebras catalog
      api_key: os.environ/CEREBRAS_API_KEY

  - model_name: balanced
    litellm_params:
      model: gemini/gemini-2.5-flash    # in China, swap for a Chinese provider
      api_key: os.environ/GOOGLE_API_KEY

  - model_name: local-floor
    litellm_params:
      model: openai/qwen-3-coder
      api_base: http://localhost:8080/v1
      api_key: not-needed

router_settings:
  routing_strategy: simple-shuffle
  fallbacks:
    - fast-pool: ["balanced", "local-floor"]
    - balanced: ["local-floor"]
```

Run it. LiteLLM reads keys from environment variables (`os.environ/...` in the config), so load the `.env` first. Recent LiteLLM won't start without its own model gateway key `LITELLM_MASTER_KEY` — the first line below creates it once. `--host 127.0.0.1` closes the model gateway to the rest of the network:

<OsBlock os="mac">

```bash
echo "LITELLM_MASTER_KEY=sk-$(od -An -tx1 -N24 /dev/urandom | tr -d ' \n')" >> ~/.config/litellm/.env   # once
set -a; source ~/.config/litellm/.env; set +a
litellm --config ~/.config/litellm/config.yaml --port 4000 --host 127.0.0.1
```

</OsBlock>

<OsBlock os="windows">

```powershell
Add-Content $HOME\.config\litellm\.env ("LITELLM_MASTER_KEY=sk-" + [guid]::NewGuid().ToString("N") + [guid]::NewGuid().ToString("N"))   # once
Get-Content $HOME\.config\litellm\.env | ?{ $_ -match '^\s*[^#].*=' } | % { $k,$v = $_ -split '=',2; Set-Item "env:$k" $v }
litellm --config $HOME\.config\litellm\config.yaml --port 4000 --host 127.0.0.1
```

</OsBlock>

Now every agent can point at `http://localhost:4000` as an "OpenAI-compatible API".

## Step 4: Local fallback (llama-server)

For when every cloud goes dark at the same time (it happens):

Download model (via HuggingFace mirror) in China: https://hf-mirror.com replaces huggingface.co. If huggingface.co doesn't open in Russia, try the same mirror.

<OsBlock os="mac">

```bash
curl -LO https://hf-mirror.com/Qwen/Qwen3-Coder-30B-A3B-Instruct-GGUF/resolve/main/Qwen3-Coder-30B-A3B-Instruct-Q4_K_M.gguf
```

</OsBlock>

<OsBlock os="windows">

```powershell
Invoke-WebRequest -Uri "https://hf-mirror.com/Qwen/Qwen3-Coder-30B-A3B-Instruct-GGUF/resolve/main/Qwen3-Coder-30B-A3B-Instruct-Q4_K_M.gguf" -OutFile "Qwen3-Coder-30B-A3B-Instruct-Q4_K_M.gguf"
```

</OsBlock>

Run llama-server (needs llama.cpp):

```bash
llama-server -m Qwen3-Coder-30B-A3B-Instruct-Q4_K_M.gguf --port 8080 -c 65536
```

> 💡 Qwen3-Coder-30B needs 32 GB RAM: the Q4_K_M file is about 18–19 GB. On 16 GB, choose a model up to 8B. `-c 65536` is there because Hermes needs a model context of at least 64K tokens, and llama-server's default is smaller; the context also takes a few more gigabytes of RAM.

## Step 5: Wire up an agent

The course agent is Hermes ([NousResearch/hermes-agent](https://github.com/NousResearch/hermes-agent)) — the one the author uses. The quick-install script has already connected it to the model gateway. By hand:

<OsBlock os="mac">

```bash
curl -fsSL https://hermes-agent.nousresearch.com/install.sh | bash   # official installer
hermes config set model.provider custom
hermes config set model.base_url http://127.0.0.1:4000/v1
hermes config set model.default fast-pool
hermes config set model.key_env LITELLM_MASTER_KEY
grep '^LITELLM_MASTER_KEY=' ~/.config/litellm/.env >> ~/.hermes/.env
hermes
```

</OsBlock>

<OsBlock os="windows">

```powershell
iex (irm https://hermes-agent.nousresearch.com/install.ps1)   # official installer
hermes config set model.provider custom
hermes config set model.base_url http://127.0.0.1:4000/v1
hermes config set model.default fast-pool
hermes config set model.key_env LITELLM_MASTER_KEY
Select-String -Path $HOME\.config\litellm\.env -Pattern '^LITELLM_MASTER_KEY=' | ForEach-Object { $_.Line } | Add-Content $env:LOCALAPPDATA\hermes\.env
hermes
```

</OsBlock>

The same, interactively: `hermes model` → "Custom endpoint". In Russia, use `balanced` (GigaChat) instead of `fast-pool`. Hermes needs a model context of at least 64K tokens and won't start with less.

Any other OpenAI-compatible agent connects with the same three values: address `http://127.0.0.1:4000/v1`, key `LITELLM_MASTER_KEY`, model `fast-pool`.

Done. Full agentic workflow without Anthropic, without OpenAI, without VPN.
