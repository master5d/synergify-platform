<Phase type="reflection">

**Jagged Intelligence** = the model shines in some tasks and faceplants in others, and the "easy/hard" logic **doesn't match** human intuition.

What AI does easily:
- Rewrite a long text in a different style
- Find patterns in logs
- Generate boilerplate code
- Summarize a meeting
- Translate between languages

What AI does poorly:
- Precise counting (characters, numbers, array indices)
- Event chronology ("what happened first — A or B")
- Geometry and spatial reasoning
- Access to fresh data without tools
- Holding long contexts without loss

That's how today's models behave, and it's worth designing the system around it.

Don't picture this as "uneven AI" — picture it as a **circus juggler** keeping balls, rings, and clubs airborne at once. Each object has its own rhythm and release angle. The juggler doesn't "catch everything the same way" — they **know which object needs which treatment**.

**Takeaway for agent engineering:** you don't "delegate a task to AI." You **break the task into objects**:
- The ones AI keeps airborne easily → hand them over
- The ones AI drops → give it a **tool** (calculator, DB, search)
- The ones that are critical → **verify** with a second model or a human

Notice: in your task — which object does the juggler carry confidently, and which one is dangerous to toss their way?

</Phase>

<Phase type="concept">

**Delegation map** (Jagged Intelligence Literacy):

```
┌─────────────────────────────────────────────────┐
│  AI nails it   │ AI with a tool    │ Human     │
├─────────────────┼───────────────────┼───────────┤
│ Text-to-text   │ Precise counting  │ Meaning   │
│ Stylization    │ Fresh data        │ Taste     │
│ Code templates │ Long memory       │ Ethics    │
│ Summarization  │ Exact math        │ What &    │
│ Translation    │ External APIs     │ why       │
└─────────────────┴───────────────────┴───────────┘
```

**Taste rule for the agent engineer:**

> *Delegate execution to AI. Keep direction and verification for yourself.*

This means:
- You choose — **what to build**
- AI writes — **the code that does it**
- You verify — **that the result matches the intent**
- AI fixes — **what you flagged as wrong**

**Real example: a Gmail agent**

My Gmail agent checks new incoming mail about every two minutes: it assigns one of five labels and prepares a draft when a reply is needed. The full diagram is in u3.

```
Poll                   ← Gmail API, not AI
  ↓
Normalize              ← code, standardize the email
  ↓
Classify               ← LLM chooses one of five labels
  ↓
Apply                  ← code adds the label or archives
  ↓
Draft                  ← LLM writes a reply draft when needed
  ↓
Review → Send          ← a human clicks a button, then Gmail API sends
```

AI appears in exactly **two of seven steps**: classification and drafting. Everything else is deterministic code, Gmail API work, or a human decision. The labels are `AI/Now`, `AI/Later`, `AI/FYI`, `AI/Newsletter`, and `AI/Ignore`; their meanings come from the specification, not a guess.

That's what agent engineering is — a **designed** combination of AI nodes and non-AI nodes.
