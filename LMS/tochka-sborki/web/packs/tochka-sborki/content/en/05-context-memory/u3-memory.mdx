> 💡 **Not just Claude Code.** A rules file is the "persistent context file" pattern, and it has a shared standard: `AGENTS.md`. Codex, Cursor, GitHub Copilot, Antigravity, Hermes and other agents read it on their own. Claude Code has its own `CLAUDE.md`, so that file holds one line, `@AGENTS.md`, which imports the shared file. The concept is universal: context lives in a file, the agent reads it at session start.

<Phase type="activation">

When you start a new Claude Code session — what do you re-explain every time?

Don't think of it as "instructions" — picture it as **a tree's growth rings**: every season leaves its mark directly in the wood — drought, growth, frost — all encoded into the structure, not stored in a separate archive. The tree doesn't "remember" last year; it's made of it.

Run your work with the agent through your head: what from your experience has already grown into the project's structure? What hasn't taken root yet — still spoken aloud each time, as if for the first time?

</Phase>

<Phase type="reflection">

Explaining the same thing every time burns time and tokens.

But there's the opposite problem too: an AGENTS.md with a thousand lines is worse than a short one — up to ~200 lines. The longer it is, the worse the agent follows instructions.

Don't picture this as a short summary — picture yourself as **a weaver at the loom**: the warp threads are pulled taut and precise — that tension is what holds the whole fabric. Add too many threads at once and the cloth sags, the loops tangle.

Notice your memory system: where is the tension just right, and where is it already sagging under extra threads? What holds the shape, and what loosens the weave?

</Phase>

## Memory files: three you write, one Claude writes

### AGENTS.md — project context and rules (the main one)

One file for everything the agent must know in every session: who you are, what the project is, how to work and what not to do. Any agent reads it. Claude Code imports it through a `CLAUDE.md` with the single line `@AGENTS.md`.

```markdown
# AGENTS.md

## My role
[Profile, expertise]

## Project
[What this is, why it exists]

## Stack
- Node.js 18, TypeScript, React

## Structure
- /src — code
- /tests — tests

## How to run
npm install && npm run dev

## What to delegate
- Writing code, tests, docs

## What I decide myself
- Architecture, final review

## Rules
- Write tests alongside code
- Show a plan before a big change

## What to avoid
- Don't change architecture without sign-off
```

**Limit: up to ~200 lines.** More than that and instruction-following degrades.

In a big project you can put a separate `AGENTS.md` into a subfolder: the agent picks it up when it works there. For a first project one file in the root is enough.

### TODO.md — current tasks

```markdown
## 🔴 NOW
- [ ] Task 1 (2 h)

## 🟡 NEXT
- [ ] Task 2

## ✅ DONE
- [x] Task 3
```

### STATE.md — where you stopped

A new session starts from a blank slate. STATE.md gives it the picture back in a minute. Update it at the end of a session, or ask the agent: "save the state".

```markdown
## Where we are
[What we are working on]

## Done
- …

## Blockers
- …

## Next step
[One action]
```

### MEMORY.md — Claude's auto-memory

Unlike the three files above, Claude **writes MEMORY.md itself**.

What it saves: patterns, fixes, project quirks.
Where it lives: `~/.claude/projects/<project>/memory/MEMORY.md` — local only.
Management: `/memory` — view and edit.

The boundary is simple: Claude decides what goes into MEMORY.md, and only Claude on your computer sees that memory. A rule that must hold for sure (say, after you fixed an agent mistake) you write yourself — in AGENTS.md.

<Phase type="practice">

Create your memory system:

<OsBlock os="mac">

```bash
mkdir -p ~/my-ai-project
cd ~/my-ai-project
touch AGENTS.md TODO.md STATE.md
echo '@AGENTS.md' > CLAUDE.md
```

</OsBlock>

<OsBlock os="windows">

```powershell
New-Item -ItemType Directory $HOME\my-ai-project -Force
cd $HOME\my-ai-project
ni AGENTS.md, TODO.md, STATE.md -ItemType File
Set-Content CLAUDE.md '@AGENTS.md'
```

</OsBlock>

Fill in AGENTS.md using the template above — use a real project or a task from your work.

Add at least 3 tasks to TODO.md that you actually have right now.

Launch Claude Code and ask: `"What do you know about my project?"`

Save the answer to `my-experiments/u3-memory-test.md`
