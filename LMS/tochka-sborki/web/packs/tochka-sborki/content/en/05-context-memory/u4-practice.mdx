## When to update what

| Event | Where to update |
|---------|-------------|
| Architecture changed | AGENTS.md, the project sections |
| New stack added | AGENTS.md, "Stack" |
| Task completed | TODO.md |
| Session ended | STATE.md: where you stopped, what's next |
| Agent made a mistake you fixed | AGENTS.md, "Rules" |
| Mid-session clarification the agent must keep using | A normal message in the session (or a rule in AGENTS.md if later sessions need it too) |

`/btw` doesn't fit here: it's a side question about the current session, and it isn't added to the conversation history.

## From mistake to check

A rule in AGENTS.md is the first step, not the last: the agent can miss a rule or lose it in a long session, but it can't get around a check. The stabilization loop:

1. **Mistake** — the agent did the wrong thing.
2. **Rule** — a short ban or requirement in AGENTS.md: "NEVER…", "ALWAYS…".
3. **Reference example** — a sample of the right result next to the rule: a file, a test, a commit.
4. **Check** — something that catches the violation without you: a test, a linter, a Hook (module 07).

A rule without a check is a wish. After a mistake, don't ask "why is the agent like this" — ask "which tool, constraint, or document was it missing".

## Techniques for long sessions

### Context compression

At the start of a new session or when context fills up:

`/compact` compresses the history into a summary; `CLAUDE.md` is reloaded afterwards. Use it when context is full or the task has changed. The universal route for any agent is to ask for a short summary manually and start a new session with it.

```
Briefly summarize what's been done and the state of the project.
Use format: ✅ Done / ❌ Left / ⚠️ Issues
```

### Prioritizing information

```markdown
## ⚠️ CRITICAL (always keep in focus)
[The most important for the current task]

## 📋 CONTEXT (good to know)
[Additional details]
```

### Parallel agents for big tasks

For independent subtasks, run several agents: open two terminals with two sessions in different folders, or launch a subagent; module 08 covers orchestration.

```
Agent 1: Sort incoming emails by topic and urgency.
Agent 2: Prepare a short report from the sorted emails.
Agent 3: Draft a reply to an email that needs a response.

Then merge the results.
```
