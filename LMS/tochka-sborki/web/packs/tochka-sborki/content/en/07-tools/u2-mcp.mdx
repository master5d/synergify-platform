## MCP: three primitives

| Primitive | Controlled by | What it is |
|----------|-------------|---------|
| **Tools** | The model | Functions the agent calls: API requests, writing files |
| **Resources** | The application | Data sources (like GET requests): files, DB records |
| **Prompts** | The user | Templates for optimal usage |

## How to connect an MCP server

The simplest way is a terminal command, run from the project folder. For example, the official Brave search server:

```bash
claude mcp add --scope project brave-search -- npx -y @brave/brave-search-mcp-server
```

The server needs a Brave API key — the package README says how to pass it.

For other servers, take the package name from their README: names change, and the current one is always there. The README also says how to pass the token. The official GitHub server is `github/github-mcp-server`: it has a remote address `https://api.githubcopilot.com/mcp/` and a Docker image, and its README describes how to connect. The old `@modelcontextprotocol/server-github` and `@modelcontextprotocol/server-brave-search` packages are archived and no longer updated.

With `--scope project`, Claude Code writes the server into `.mcp.json` at the project root — shared with the team and kept in git. You can also edit it by hand:

```json
{
  "mcpServers": {
    "brave-search": {
      "command": "npx",
      "args": ["-y", "@brave/brave-search-mcp-server"]
    }
  }
}
```

Personal servers (scope `user` or `local`) live in `~/.claude.json`. Don't put MCP servers in `.claude/settings.json` — Claude Code doesn't read them from there.

## Popular MCP servers

| Server | What it gives you |
|--------|---------|
| `github/github-mcp-server` (official, from GitHub) | Issues, PRs, commits, repo files |
| `@modelcontextprotocol/server-filesystem` | Extended file system access |
| `@brave/brave-search-mcp-server` (official, from Brave) | Searching the web |
| Notion MCP | Read and write Notion pages |
| Firecrawl | Web page scraping |

## Common errors (~60% of issues)

- `Server transport closed unexpectedly` — syntax error in the JSON config
- Port conflicts — two servers trying to listen on the same port
- Missing env var — token wasn't passed correctly

Fix: check JSON syntax and tokens before digging deeper.
