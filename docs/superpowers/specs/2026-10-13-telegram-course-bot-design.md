# Платформа: курс в Telegram-боте с чатом по материалам

Дата: 2026-10-13. Источник: BACKLOG.md, пункт «Платформа: курс в Telegram-боте с чатом по материалам» (intake LMS#1):
вход в pack через бота — мини-курс + вопросы по курсу. Внешний образец тьютора по корпусу — NAUTILUS `/tutor`
(в этом репо его нет, здесь не цитируется). Статус: **черновик спеки, кода нет; ждёт решений владельца**

## Цель и не-цели

**Цель.** Человек, у которого есть только Telegram, проходит короткий путь курса прямо в чате бота: получает юнит,
отвечает на самопроверку, идёт дальше; в любой момент спрашивает «что в материалах про X» и получает ответ по тексту
курса со ссылкой на урок. Прогресс общий с сайтом: юнит, закрытый в чате, закрыт и на сайте, и наоборот.

**Не-цели.**
- Не второй интерфейс к LLM: ни свободного «чата с ИИ», ни выбора модели. Только одна узкая операция «ответ по
  материалам» в `llm-service` (как остальные пять, `llm-service/README.md:8-9`).
- Не замена сайта: полный урок (MDX, картинки, фазы) остаётся на сайте / в Mini App; чат даёт карточку юнита и
  самопроверку, а не переписанный в Telegram урок.
- Не замена куратора: `/ask` (вопрос человеку) остаётся как есть.
- Не продажи, не воронка: см. «Границы».
- Не включаем для «Тишины» по умолчанию.

## Пользовательский поток

### Вход
1. Человек открывает `t.me/<бот>?start=<pack>` (ссылка с сайта курса, из сообщества, из поста). Без payload —
   pack по умолчанию (`tochka-sborki`). Неизвестный или выключенный pack — честный текст + кнопка на сайт курса.
2. Бот находит пользователя по `telegram_id`; если нет — **см. вопрос В2** (заводить ли пользователя ботом).
3. Бот показывает рамку входа pack'а (`entryFrame`, см. «Границы») и две кнопки: «Начать мини-курс» и «Спросить по
   материалам».

### Мини-курс в чате: юнит → самопроверка → следующий
1. **Карточка юнита**: название модуля и юнита, цель модуля (`objectives`), 3–5 пунктов «о чём урок» (источник — В5) и
   `web_app`-кнопка «Открыть урок» (Mini App, `telegram-api.ts:8`) — урок читается целиком там, вход сквозной через
   auth-мост.
2. **Самопроверка**: после «Прочитал» бот задаёт вопросы юнита из `checks` — вопрос + варианты кнопками
   (callback). Воркер сверяет с `answer` сам, **без LLM**; после ответа — верный вариант и `explain` (как веб-`SelfCheck`,
   спека 2026-09-14 §3). Попытки без лимита, без баллов. Юнит без `checks` — шаг «Отметить пройденным».
3. **Отметка прогресса**: та же строка `progress`, что пишет сайт (`module/unit`, колонка `course`; запись —
   `workers/src/handlers/progress.ts:32-36`), чтобы допуск/сертификат/письма видели прогресс из чата. Если включён
   интервальный повтор (`SPACED_REVIEW_ENABLED`, `workers/src/lib/check-reviews.ts:17-19`) — ответ идёт и в
   `check_reviews` (только верно/нет, `workers/migrations/0022_check_reviews.sql:1-4`).
4. **Следующий**: кнопка «Дальше» → карточка следующего юнита по порядку `_meta.json`; «Продолжу потом» — бот
   запоминает место, `/continue` возвращает в него (сейчас `/continue` знает только модули — `workers/src/lib/course-order.ts:88-93`).
5. Конец мини-курса: короткое «что дальше» — ссылка на полный курс на сайте. Без продаж.

### «Спросить по материалам»
1. Ученик пишет вопрос (кнопка или команда — имя команды В7). Пока юнит открыт — контекст по умолчанию этот юнит.
2. Бот сразу отвечает «Ищу в материалах…» и `typing`; ответ приходит отдельным сообщением.
3. Ответ: 2–6 предложений **только** по найденным фрагментам курса + 1–3 ссылки «где это в курсе» (урок на сайте).
   Если в материалах ответа нет — прямо: «в материалах курса этого нет», без своей импровизации под видом курса
   (правило движка `LMS/tochka-sborki/web/lib/learn-prompt-reference.ts:71-74`), и предложение `/ask` куратору.
4. Вопрос «какой правильный ответ на самопроверку / сделай практику за меня» — наводящий вопрос, не ответ (см.
   «ИИ сделал за меня»).
5. Сбой сервиса — честный текст (см. «Отказ»), не тишина.

## LLM: новый маршрут и где брать материал

### Маршрут `POST /course-qa` в `llm-service`
- Тело: `{ question, locale, course, passages: [{ id, text, title, url }] }`, `passages` ≤ k (напр. 6), каждый ≤ ~1200
  символов. Промпт фиксирован в сервисе (как `prompts.ts`), вопрос ученика — данные, а не инструкция.
- Ответ: `{ answer, cited: string[], inMaterials: boolean }`. Сервис проверяет `cited ⊆ passages[].id` (иначе
  `bad_shape`), воркер перепроверяет ещё раз — тот же двойной заслон, что у русла задачи (`workers/src/handlers/task-route.ts:6`).
- Пул — новый алиас `POOL_COURSE_QA` в `llm-service/src/config.ts` (значение по умолчанию — В9), температура низкая
  (`gateway.ts` уже принимает `temperature`/`timeoutMs`). Ни имени модели, ни ключа в воркере.
- Тесты сервиса — фейковый `fetchImpl`, как у существующих операций.

### Где брать материал (retrieval) — варианты (решение В4)
| | Что индексировать | Где хранить | Плюсы | Минусы |
|---|---|---|---|---|

| **B. Чанки MDX в бандле воркера** | весь текст уроков pack'а, порезанный по заголовкам; детерминированный генератор рядом с `gen-lesson-views.ts`, со `sourceHash`-гвардом | `packs/<pack>/qa-index/{ru,en}.json`, импорт в воркер; поиск — BM25/ключевые слова в воркере | без LLM в поиске, офлайн-проверяемо, один источник правды — MDX | +~0,8 МБ на ТС в бандл воркера (проверить лимит плана); поиск лексический |

### Запрещено
Сырые имена моделей, провайдерские SDK и ключи в воркере (`AGENTS.md`; `docs/README-internal.md:87-95`); прямой

## Границы

### Бесплатность и «без встроенных продаж»
- Обещание pack'а — `entryFrame` (`packs/tochka-sborki/dictionaries.ts:248-252`, текст `:560-564`), застраховано
  правилом манифеста «встроенная продажа» (`packs/tochka-sborki/manifest.ts:11-20`).
- В чат-курсе: ни одного платного шага, ни «лимит исчерпан — поддержи автора», ни ссылок `/support`/`/store` в
  карточках, ответах тьютора и сообщениях о квоте. Эти команды отвечают **только** на явный вызов (как сейчас).
- Новые тексты бота прогоняются тем же манифестом pack'а (тест). Исчерпанная квота — «на сегодня вопросы
  закончились, завтра снова; урок открыт» + `/ask` куратору.
- У «Тишины» `entryFrame` в словаре не заполнен (поле опционально — `packs/living-practice/dictionaries.ts:252`):
  рамка входа в бот для неё — часть В3.

### Приватность (репо публичный)
- В репо — ни реальных вопросов учеников, ни логов, ни `telegram_id`: фикстуры тестов только синтетические.
- По умолчанию текст вопросов к тьютору и ответы **не хранятся**; в логах воркера — только код исхода
  (`ok / not_in_materials / rate_limited / unavailable:<code>`), без текста. Счётчики — по `user_id` и дню.
- Прецедент обратного: `/ask` хранит текст вопроса и `telegram_id` (`workers/migrations/0010_questions.sql`,
  `telegram-webhook.ts:81-83`) — это вопрос **человеку**, с явным «передам куратору» (`bot-copy.ts:45-46`). Тьютор так
  не делает без решения В6.
- Ответы на самопроверки — только верно/нет (как `check_reviews`).

### Защита от «ИИ сделал за меня»
- Правило движка — `REFERENCE_RULES` (`LMS/tochka-sborki/web/lib/learn-prompt-reference.ts:52-79`): не раскрывать
  эталон и верные ответы самопроверок «ни целиком, ни по частям», направлять вопросом, разбор — только после попытки.
  Операция `/course-qa` несёт те же правила в своём фиксированном промпте (одинаковы для любого pack'а).
- В `passages` для тьютора `checks` идут **без** поля `answer` и без `explain` до того, как ученик ответил на вопрос в
  чате; эталоны практик (`practice-references.ts`) — только как скрытый ориентир под правилом «не раскрывай».
- Детерминированный пост-гвард в воркере: если ответ модели содержит текст верного варианта неотвеченной
  самопроверки текущего юнита — ответ заменяется наводящим текстом. Тест на это.
- Честно: верные ответы и так лежат в статическом бандле сайта (`_meta.json` публичный) — правило педагогическое
  (не подсовывать готовое), а не секретность.

### Стоимость, квоты, таймауты
- Главный выключатель `TUTOR_CHAT_ENABLED` (wrangler var, `"0"`), по аналогии с `COMMUNITY_INVITES_ENABLED`
  (`workers/src/lib/types.ts:26-27`). Мини-курс без LLM включается отдельно от тьютора.
- Лимиты: на ученика (мягкий — `hitRateLimit`, `rate-limit.ts:37`; жёсткий — `tutor_usage`) и общий дневной потолок
  на весь бот (В8). Вызов, не дошедший до модели (пустой вопрос, нет фрагментов), квоту не тратит — как в
  `workers/src/handlers/task-route.ts:39`.
- Таймауты: Telegram держит вебхук недолго и повторяет неотвеченные апдейты, а `callLlm` по умолчанию ждёт до 100 с
  (`llm-client.ts:18`). Поэтому: вебхук отвечает `200` сразу, вызов тьютора — в `ctx.waitUntil` (нужно передать `ctx`
  в `handleTelegramWebhook`, сейчас не передаётся — `workers/src/index.ts:83`), свой короткий потолок `COURSE_QA_TIMEOUT_MS`
  (~25 с, меньше лимита фоновой работы воркера — проверить на текущем плане) и внутри сервиса — меньше этого.
  `sendMessage` получает таймаут (сейчас его нет — `telegram-api.ts:10-14`; правило «таймауты на всей сети», `AGENTS.md`).
- Длина ответа ≤ лимита сообщения Telegram (4096 символов); `callback_data` кнопок ≤ 64 байт — id вопроса и шага,
  не текст.

### Отказ при недоступном `llm-service`
Любой не-2xx/таймаут `callLlm` (`llm-client.ts:51-55`) → ученику **сразу** текст: «Сейчас не получается ответить по
материалам — сервис ответов недоступен. Урок открыт, а вопрос можно передать куратору: /ask». В лог — код отказа
(урок `/skin`, `workers/src/handlers/task-route.ts:59-60`). Мини-курс при этом работает целиком: он от LLM не зависит.

### Изоляция pack'ов
- Включение — по флагу pack'а, не по имени: новое поле `features.botChat` (и отдельно `botTutor`) в
  `course.config.ts` каждого pack'а (рядом с `features`, `packs/tochka-sborki/course.config.ts:30`;
  `packs/living-practice/course.config.ts` — `features` там же). Ядро гейтит по флагам, а не по имени
  (`docs/README-internal.md:35-37`).
- Тьютор отвечает только по фрагментам **своего** pack'а; фрагмент чужого pack'а в ответе — красный тест (как
  «компаньон называет свой курс и никогда чужой», `docs/README-internal.md:53-55`).
- **«Тишина» — по умолчанию выкл.** Курс деликатный: границы компаньона — не толковать ощущения, не ставить
  диагнозов, не повышать дозу практики (`packs/living-practice/course/companion.ts:52-62`); пересказы уже однажды
  искажали смысл, поэтому конспект там дословный (`packs/living-practice/course.config.ts:21-24`); у курса ворота
  допуска академии (`gates.admission: true`, `packs/living-practice/course.config.ts:43`) — вход через бота не должен
  их обходить. Включать ли там мини-курс и/или тьютора — В3.

## Срезы реализации

| Срез | Что | Тест приёмки |
|---|---|---|
| **S0** | Флаги: `TUTOR_CHAT_ENABLED`, `BOT_COURSE_ENABLED` (env), `features.botChat`/`botTutor` в обоих pack'ах (ТС — по решению В1, «Тишина» — `false`). Таймаут в `sendMessage`. | при `"0"` и при `false` у pack'а новые ветки вебхука не исполняются и не ходят в D1/LLM; `sendMessage` обрывается по таймауту (фейковый fetch) |
| **S1** | Deep-link `/start <pack>`: `parseUpdate` несёт payload; pack из `LMS/registry.json`; неизвестный/выключенный → текст + сайт; заведение пользователя по В2; рамка входа. | `parseUpdate('/start living-practice')` → pack; неизвестный → дефолт; выключенный pack → без карточки; «Тишина» не открывается мимо допуска |
| **S2** | Мини-курс: `bot_sessions`, карточка юнита (`web_app` на урок), вопросы `checks` кнопками, проверка в воркере, запись `progress` (`module/unit` + `course`), «Дальше»/`/continue` по юнитам. | верный вариант и `explain` показываются только после ответа; строка `progress` совпадает с той, что пишет сайт; `/continue` ведёт в незакрытый юнит; `callback_data` ≤ 64 байт для всех `checks` обоих pack'ов |
| **S3** | Источник фрагментов: вариант A (юнит-контекст) — сразу; вариант B/C/D — по В4: детерминированный генератор, `sourceHash`-гвард свежести как у views. | правка MDX без перегенерации индекса — красный тест; в индексе нет `answer`; размер бандла воркера под порогом |
| **S4** | `llm-service`: `POST /course-qa`, фиксированный промпт с `REFERENCE_RULES`, `POOL_COURSE_QA`, свой таймаут, проверка `cited ⊆ passages`. | фейковый гейтвей: цитата вне `passages` → `bad_shape`; таймаут → `timeout`; без bearer → 401; в коде нет имён моделей |
| **S5** | Тьютор в воркере: выбор фрагментов, `callLlm` в `ctx.waitUntil`, пост-гвард эталона, лимиты, отказ, исчерпанная квота. | сбой сервиса → текст отказа отправлен (не тишина); ответ с верным вариантом неотвеченного вопроса заменён; квота: N+1-й вопрос — текст квоты без продаж (манифест pack'а зелёный на новых строках бота) |
| **S6** | Владельцу: счётчики (вопросов, `not_in_materials`, отказов) в `/api/admin/stats`, без текстов. | эндпоинт owner-gated; в ответе нет текстов вопросов |

Каждый срез — свой PR; приём — `npm test` веба под оба pack'а, тесты `workers/` и `llm-service/`, `tsc`.

## Вопросы владельцу

**В1. Что такое «мини-курс» для ТС?**
(a) весь курс по юнитам; (b) только модуль `00-kickstart` (5 юнитов, `views/ru/00-kickstart/`) как пробник, дальше —
сайт; (c) отдельный кураторский путь из 5–7 юнитов разных модулей (новые данные pack'а).
Рекомендация: **(b)** — короткий, уже с самопроверками, не надо решать, что вырезать.

**В2. Заводить ли пользователя ботом без входа через Mini App?**
(a) да, синтетический `tg_<id>@telegram.local` при первом шаге мини-курса (как auth-мост); (b) нет — первый шаг
мини-курса просит «открой урок» (Mini App), и пользователь появляется через мост; (c) состояние в `bot_sessions`
по `telegram_id` без `users`, привязка при первом входе.
Рекомендация: **(b)** — одна точка создания пользователей и проверенный подписанный `initData`; кнопка «Открыть урок»
всё равно есть на каждой карточке.

**В3. «Тишина» в боте.**
(a) ничего — выключено; (b) только мини-курс (карточки + самопроверки рамки безопасности), без тьютора, и только после
допуска академии; (c) мини-курс + тьютор с границами компаньона «Тишины».
Рекомендация: **(a)** сейчас; к (b) вернуться после опыта ТС.

**В4. Где искать материал для ответа** — варианты A/B/C/D выше.
Рекомендация: **A сразу, B основным** (детерминированный индекс в бандле воркера).

**В5. Пункты карточки юнита.**
(a) из views (`outline`, как есть, тонко); (b) новое авторское поле в `_meta.json` юнита — 3–5 строк «о чём урок»
(пишет агент автора, вычитывает владелец); (c) только название + цель модуля, всё остальное — в Mini App.
Рекомендация: **(c)** на старте, **(b)** если чат станет основным входом.

**В6. Хранить ли тексты вопросов к тьютору?**
(a) нет, только счётчики; (b) хранить вопросы «не нашлось в материалах» как сигналы спроса (обезличенно, срок 90 дней),
с предупреждением в боте; (c) хранить всё.
Рекомендация: **(a)**; (b) — если нужен сигнал о пробелах курса, с явной строкой в боте.

**В7. Команды.**
(a) `/ask` остаётся «куратору», новая команда для тьютора (например `/q`); (b) `/ask` становится тьютором, куратор —
кнопкой «передать человеку» под ответом; (c) без команды — любой свободный текст в режиме вопроса.
Рекомендация: **(a)** — не меняем смысл того, что уже работает.

**В8. Квоты.**
(a) 10 вопросов в день на ученика, мягко (Cache API, без миграции); (b) то же жёстко (`tutor_usage` в D1) + общий
потолок на бот в день; (c) без персонального лимита, только общий потолок.
Рекомендация: **(b)**: Cache API — per-colo и неатомарен (`rate-limit.ts:4-6`), а за вызовом — квота гейтвея.

**В9. Пул гейтвея для `/course-qa`.**
(a) `draft-pool` (как пересказ примера, `llm-service/src/config.ts:34`); (b) `prose-pool`; (c) отдельный новый алиас
в гейтвее лаборатории под эту операцию (видно в учёте отдельно).
Рекомендация: **(c)**, по умолчанию в коде — `draft-pool`, пока алиас не заведён.

**В10. `/support` и `/store` в боте курса.**
(a) оставить как есть — только по явной команде; (b) убрать `/store` из бота курса (магазин — личный сайт,
`workers/src/lib/course-order.ts:122-125`), `/support` оставить; (c) убрать обе из бота, где идёт мини-курс.
Рекомендация: **(a)** — обещание `entryFrame` касается «внутри курса»; явный ответ на команду — не встроенная продажа.
Решение — за владельцем.

**В11. Тексты бота.** Приветствие, карточки, отказ, квота — черновик агента на вычитку владельцем (как `entryFrame`)?
Рекомендация: да, через Logos Foundry, RU и EN одним коммитом.
