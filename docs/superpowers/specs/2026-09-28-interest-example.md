# ТС: пример из интереса ученика в концепт-фазе — спека

Дата: 2026-09-28. Источник: intake LMS#8 (Google Learn Your Way, arXiv 2509.13348), строка BACKLOG
«ТС: пример из интереса ученика в концепт-фазе», **принято владельцем 2026-09-14**, «спека до кода».

## Зачем

Анкета знает сферу ученика (`intake_profiles.niche` ← ответ `V_NICHE`), а примеры в концепт-фазе у всех одни.
Скины меняют только оформление. Learn Your Way подменяет общий пример примером из интереса ученика.
Мы берём узкую версию: **один размеченный пример в юните пересказывается через сферу ученика**. Факты, цифры
и команды остаются как в исходнике. Любой сбой показывает общий пример, и ученик ничего не теряет.

## Что НЕ делаем

- Не переписываем весь юнит и не меняем уровень текста. Меняется только размеченный пример.
- Не персонализируем все примеры подряд. Только те, что автор пометил явно (см. «Разметка»).
- Не принимаем свободный текст интереса. Ключ кэша строится только из закрытого списка.
- Не ходим в провайдеров мимо `llm-service` и гейтвея SOVERN.

## Разметка: какие юниты

1. **Данные** — `packs/<pack>/course/interest-examples.ts`: список `{ module, unit, id, text: { ru, en } }`.
   `text` — общий пример, 1–3 абзаца прозы, допускается инлайн-код в `` `…` ``. Кодовых блоков, таблиц и ссылок
   в персонализируемом примере нет: такой пример переписывать нельзя по контракту, его не размечаем.
2. **Метка** — в MDX юнита, внутри `<Phase type="concept">`: `<InterestExample id="…"/>` (как `<SelfCheck id/>`).
3. Данные лежат в файле pack'а, а не в `_meta.json`. Причина — граница доверия: исходный текст должен знать
   **воркер**, а не клиент. Иначе авторизованный клиент мог бы прислать любой текст и гонять наш LLM как
   переписчик общего назначения. Воркер уже импортирует модули веба (`intake.ts` → `lib/intake/scoring`).
4. Гвард `lib/interest-example/registry.test.ts`: каждая метка имеет запись, каждая запись имеет метку в RU и EN.
   Исходник чист по манифесту pack'а, у него нет кодовых блоков и ссылок, а длина ≤ 1200 символов.

**Пилот (3 юнита ТС):** `01-introduction/u2-four-shifts` (сдвиг «от команд к делегированию»),
`05-context-memory/u2-context-vs-prompt` (пример «контекст vs промпт» вынесен из кодового блока),
`10-model-training/u2-data-is-the-work` (пары «вход → правильный выход»). У `living-practice` список пуст.

## Интерес → ключ

Закрытый список = значения `V_NICHE` без `other`: `coach · massage · astrology · content · ecommerce · service · tech`
(`lib/interest-example/interests.ts`; гвард сверяет его с опциями `V_NICHE` обоих pack'ов).
`niche` пустой, `other` или вне списка → персонализации нет, показываем общий пример.
Кэш поэтому конечен: ≤ 7 интересов × 2 локали × размеченные примеры (пилот: 42 пары).

Интерес берёт **воркер** из `intake_profiles.niche` по сессии, а не клиент. Клиент интерес не присылает.

## Операция `llm-service`: `POST /interest-example`

- Вход: `{ source: string, interest: Interest, language: 'ru' | 'en' | 'ru-tech' }`.
  Неизвестный язык, неизвестный интерес, пустой или длиннее 2000 символов `source` → 400 `bad_request` до гейтвея.
- Выход: `{ example: string }`.
- Промпт (фиксированный): перескажи пример так, чтобы действующие лица и ситуация были из сферы X. Сохрани мысль,
  число абзацев и примерную длину (±30 %). Не выдумывай фактов, цифр, названий продуктов и ссылок; каждое число
  бери только из исходника. Инлайн-код и команды в `` `…` `` переноси дословно. Без продажного тона, без обещаний
  результата. Язык — инструкцией (`LANGUAGE_RULES`), не токеном.
- Пул: env `POOL_INTEREST`, по умолчанию `draft-pool` (алиас гейтвея). Температура 0.4. Таймаут к гейтвею 20 с
  (свой, не общий 90 с).
- Сервис проверяет только форму: непустая строка не длиннее трёх исходников, иначе 502 `bad_shape`.
  Смысловую проверку делает воркер (ниже), чтобы правило жило в одном месте.

## Проверка манифестом (гвард результата)

`lib/interest-example/guard.ts` → `checkInterestExample(source, candidate, rules)` возвращает список находок.
Пустой список означает «годен». Проверки:
- длина кандидата — от 0.6 до 1.6 длины исходника;
- то же число абзацев;
- набор инлайн-кодов `` `…` `` совпадает с исходником дословно (команды и код не меняются);
- каждое число кандидата есть в исходнике (цифры не выдумываются);
- новых URL нет;
- `checkManifest` по правилам манифеста и `lintDehustle` дают 0 находок.

Воркер проверяет по объединению манифестов обоих pack'ов (строже любого) и кэширует только годное.
Клиент перепроверяет по `MANIFEST` своего pack'а перед показом.

## Кэш

**Cloudflare Cache API воркера (`caches.default`)**: без новой таблицы и без миграции. KV-биндинга у воркера нет,
а у `llm-service` кэша нет. Ключ — синтетический URL:
`https://interest-example.cache/v1/<module>/<unit>/<id>/<locale>/<interest>/<fnv1a(source)>`.
Хэш исходника в ключе сам инвалидирует кэш при правке примера.
- годный ответ: `max-age` 30 дней;
- отказ гварда: отрицательная запись на 1 час, чтобы не жечь квоту на повторах;
- сетевой сбой в кэш не пишется.

Цена решения: Cache API живёт в каждом дата-центре CF отдельно и может вытесняться. Пара генерируется заново
в каждом новом колокейшне. При ≤ 42 парах это копейки. Если понадобится глобальный и вечный кэш — таблица D1
`interest_examples` (вопрос владельцу, миграцию в этой волне не делаем).

## Лимиты, таймауты, деградация

| Звено | Таймаут | При отказе |
|---|---|---|
| клиент → `/api/interest-example` | 6 с | общий пример (он уже на экране) |
| воркер ждёт генерацию | 4 с (гонка) | `{source:'template', pending:true}`, генерация доживает в `ctx.waitUntil` и кладёт в кэш |
| воркер → `llm-service` | 25 с | лог + общий пример |
| `llm-service` → гейтвей | 20 с | 502 `timeout` |

- Клиент при `pending` повторяет запрос **один раз** через 8 с. Дальше — общий пример до следующего захода.
- Персонализация доступна только вошедшему ученику (`requireAuth`). Без сессии → 401 → общий пример.
- Прецедент деградации — `prose_source='template'` в `handlers/intake.ts`: сбой сервиса не ломает путь ученика,
  в лог воркера пишется улика. Ответ воркера несёт `source: 'interest' | 'template'` и `reason`
  (`no_interest | rejected | unavailable | pending`).

## Что видит ученик

- Общий пример рендерится статически (SSR) сразу. Мигания и спиннера нет.
- Если пришёл годный персональный пример, он заменяет общий. Над ним метка
  «Пример под твою сферу: <сфера>» / «Example for your field: <field>» и кнопка «Показать общий пример» /
  «Show the general example». Кнопка переключает обратно: «Показать под мою сферу».
- Выбор кнопки держится в состоянии экземпляра и не сохраняется. Персональные данные не уходят в аналитику.

## Тесты (обязательный минимум)

Контракт операции (400 до гейтвея, форма ответа, язык и интерес в промпте, таймаут 20 с). Кэш-ключ: детерминизм,
смена исходника меняет ключ, интерес вне списка ключа не даёт. Отказ манифеста → общий пример и отрицательный
кэш. Таймаут → общий пример. Нет интереса → общий пример без вызова сервиса. Попадание в кэш → без вызова сервиса.
Гвард разметки: метки ↔ записи, RU + EN.
