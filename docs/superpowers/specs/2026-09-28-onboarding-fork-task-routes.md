# Онбординг: развилка «криэйтор / предприниматель» + сквозная задача (русла)

Дата: 2026-09-28. Источник: BACKLOG.md, пункт «Онбординг: развилка „криэйтор / предприниматель“ + сквозная
задача через весь курс» (решение владельца 2026-09-14; трактовка «шаги реализации + какие модули пройти»
подтверждена им же). Статус: спека → реализация в ветке `w18/onboarding-fork`.

## Проблема

Студент приходит с задачей и сам выбирает дорогу — часто не ту. Пример владельца: «система, которая
производит контент для mortgage-бизнеса» кажется мультиагентной оркестрацией, а на деле это контент-пайплайн:
04 → 05 → 06 → 07. Сейчас связь «анкета → курс» — грубое `NICHE_MODULE` (ниша → один модуль) и «Карта недели»
(дело → модуль по словарю). Задачи-проекта, ведущей через весь курс, нет.

## Поток анкеты (module V, pack `tochka-sborki`)

| # | id | формат | что |
|---|----|--------|-----|
| 1 | `V_ROLE` (новый) | single | `creator` / `entrepreneur`. Сужает варианты `V_NICHE` и каталог русел. |
| — | `V_NICHE` | single | как было; у опций появляется `showIf` по роли (опции без `showIf` — обеим ролям; роль не выбрана — видны все). |
| 2 | `V_TASK_MODE` (новый) | single | `task` «есть задача» / `learn` «хочу научиться создавать». |
| 3 | `V_OUTCOME` | text | как было — свободный текст задачи (недетерминированный сигнал). Id не меняем: его уже читают проза листа, устав, подземелье (`{outcome}`). |
| 4 | `V_TASK_ROUTE` (новый) | `task-route` | только при `V_TASK_MODE = task`. Сопоставление текста с каталогом → русло. |
| — | `V_AUTO_*`, `V_WEEK_MAP` … | | без изменений. |

«Хочу научиться» → шаг `V_TASK_ROUTE` скрыт, курс идёт по порядку, русло не навязывается (все поверхности
ниже без русла ведут себя как раньше).

## Данные: `packs/<pack>/course/task-routes.ts` (course-data, стаб `lib/course/task-routes.ts`)

```ts
TASK_ROUTES: TaskRoute[]          // закрытый каталог русел, порядок = порядок в ручном списке
TaskRoute = {
  key: string                     // kebab, стабильный — хранится в answers
  roles: TaskRole[]               // для каких ролей русло в каталоге
  title, summary: {ru,en}
  classifierHint: string          // EN, одна-две фразы для модели: какие задачи сюда, какие — нет
  check: { unit }                 // шаг 0: «Стоит ли автоматизировать?» (LMS#10) — вердикт анкеты + юнит
  steps: { unit, title:{ru,en}, action:{ru,en} }[]   // упорядоченные шаги реализации, unit = '<module>/<unit>'
  falseRoad: { title:{ru,en}, why:{ru,en} }          // «не оркестрация — пайплайн: 04 → 05 → 06 → 07»
  result: {ru,en}                 // рабочий результат в конце (с {outcome})
}
TASK_ROUTE_CLARIFY: ClarifyQuestion[]   // 3 уточняющих вопроса, у опции — routes: string[] (ключи каталога)
TASK_ROUTE_COPY                         // тексты шага RU/EN
```

Каталог Точки Сборки (8): `content-pipeline`, `landing-funnel`, `reports-routine`, `support-booking-bot`,
`source-notebook`, `memory-agent`, `multi-agent-orchestration`, `fine-tune-model`. У `living-practice`
каталог пуст (вопросов развилки в его анкете нет — как у «Карты недели»).

## Классификатор (единственное недетерминированное звено)

`web (static)` → `POST /api/intake/task-route` (воркер, auth) → `llm-service POST /task-route/classify` → гейтвей SOVERN.

- Воркер берёт каталог из pack'а (`routesForRole(role)`), шлёт `{text, catalog:[{key, hint}]}`; текст 3–600 знаков.
- Сервис возвращает `{route: key|null, confidence: 'high'|'low', candidates: key[] (≤3)}`. Любой ключ вне
  присланного каталога → `bad_shape` (502): **модель не может выйти за каталог**, выдуманное русло не доезжает.
- Воркер перепроверяет ключи по каталогу (второй заслон) и отвечает 200:
  `matched {route}` (high + route) · `unsure {candidates}` (low / null) · `unavailable` (любая ошибка, таймаут 20 с).
- Промпт — только сопоставление: «выбери ключ из списка или null», без генерации шагов.

### Низкая уверенность → уточнение, не чат

`unsure` → 3 вопроса с готовыми вариантами из `TASK_ROUTE_CLARIFY`. `resolveClarify(answers, candidates, catalog)`
— детерминированно: голос опции +1 (первый вопрос «что на выходе» +2), кандидат модели +1, только ключи каталога
роли; единственный максимум → русло, ничья / пусто → ручной список с подсвеченными лидерами.

### Деградация

`unavailable`, нет сети, пустой текст, 4xx → ручной выбор русла из списка (каталог роли + «показать все»).
Анкета не блокируется: шаг необязательный. Кнопка «выбрать самому» видна всегда.

## Выход — детерминированный

Ответ `V_TASK_ROUTE = [key, source, textSnapshot]` (`source`: `llm` / `clarify` / `manual`). Из ключа всё
остальное — статические данные pack'а: тот же ключ → то же русло. Повторный заход на шаг с тем же текстом
не переспрашивает модель (снимок текста).

## Сквозная задача

`profileTaskRoute(profile)` (mode = task и ключ в каталоге, иначе null):

- **Личный план** (`learning-plan.ts` / `<LearningPlanCard>`): раздел «Твоя задача — русло»: шаг 0 (проверка),
  шаги с модулями, ложная дорога, результат. Рядом с «Картой недели», не вместо.
- **Квест-лог** (`buildQuestLog`): у зоны модуля, где есть шаг русла, — `routeStep` («шаг N: …») в ленте.
- **Подземелье / «босс модуля»**: если русло есть, модуль подземелья = модуль последнего шага русла, босс =
  результат русла с `{outcome}`. Без русла — прежний `NICHE_MODULE`. `NICHE_MODULE` остаётся фолбэком для
  «хочу научиться» и старых профилей; удаляется, когда владелец решит.
  **Поправка 2026-09-28 (решение владельца):** `NICHE_MODULE` удалён. Без русла модуль подземелья выбирается по
  прогрессу (самый дальний закрытый модуль спайна, иначе первый), ниша — только флейвор; пройденность — по модулю.

## Гварды (тесты)

1. Каждый `unit` в `check`/`steps` существует в контенте pack'а (RU и EN `_meta.json`).
2. Шаги русла идут по модулям неубывающе (сквозь курс, без возвратов).
3. У каждого русла непустые `result`, `falseRoad`, ≥2 шагов, RU+EN.
4. Ключи уникальны; каждая роль имеет ≥3 русла; ключи в `TASK_ROUTE_CLARIFY` ⊂ каталог.
5. Классификатор: ответ сервиса вне каталога → `bad_shape`; воркер на ключ вне каталога → `unsure`, на ошибку → `unavailable`.
6. `resolveClarify` детерминирован и не возвращает ключ вне каталога роли.

## Не делаем здесь

Вывод шага русла внутри юнита (концепт-фаза — зона параллельного эпика «пример из интереса ученика»); замену
`V_OUTCOME` новым id; миграций D1 (всё в `answers`).
