# Сквозная картина курса — машина, которую собирает ученик (дизайн)

**Дата:** 2026-10-12 · **Источник:** intake LMS#36 (скилл Anatomy, `wheresryan22/anatomy`, MIT) + реплика владельца:
«я хочу сквозную единую картину, в которой на каждом модуле / юните будет подсвечиваться тот узел картины, за который
отвечает модуль и юнит» — сначала Точка Сборки, потом лаборатория. Решения владельца по ходу брейншторма — в скобках
«(владелец: …)».

## Цель

Ученик на любом модуле и юните видит, какую часть целого он сейчас собирает и как она стыкуется с остальными. Картина —
не маршрут курса (это делает World Map на `/character`), а сам агентский стек ученика, изображённый изометрической
машиной в стиле Anatomy (владелец: вариант 1 — «машина, которую собирает ученик»).

## 1. Анатомия машины — автомобиль

**Метафора сменена владельцем 2026-10-12** («давай теперь попробуем на примере автомобиля, где кодинговый агент — это сам
автомобиль, токены — бензин, модели — марки бензина»; переход подтверждён «да» после листа и сцен). Прежняя машина-станок
(двигатель в центре, конвейер, револьверная головка…) снята: четыре прохода Codex не дали узнаваемой машины.

Ось — рамка курса из LMS#35 в автомобильном прочтении: **обвязка = машина, модель = топливо**; токены — литры в баке,
модели — марки топлива на колонке, шлюз к моделям — пистолет-переключатель. Модуль отвечает за узел, юнит — за деталь.

**Источник правды — паспорт автомобиля** `docs/superpowers/specs/2026-10-12-assembly-car-profile.md`: якорь машины, ракурс,
палитры, таблица 12 узлов (модуль → узел → место на сцене) и 50 деталей (юнит → деталь). Образцы генерации — PNG вне git
(`.gitignore` репо: `docs/**/*.png`) в `.superpowers/assembly-car/` основного дерева lms-engine (`sheet.png` — лист
развёртки, `hero.png` — главная сцена, `hero-alt.png`); паспорта генераций — `docs/superpowers/specs/assets/assembly-car/*.json`
(дорожка codex image_gen, C2PA — только образец, на сайт не идут). Соответствие в коде — `packs/tochka-sborki/course/assembly-map.ts`, id из паспорта.

- Каждый юнит указывает на деталь своего узла (пример: `06-audio-pipeline/u5-schedule` — таймер автозапуска у дворников).
- Юниты-фазы (activation, reflect и подобные) указывают на узел целиком: значение `'node'`, записанное явно. Умолчания нет.
- Опциональные модули (`OPTIONAL_MODULE_SLUGS`: 09, 10, 11) — атлас, диностенд, бортовой компьютер: на краю сцены; их отсутствие не
  выглядит дырой.
- Детали внутри узлов (58 юнитов на 2026-10-12) придумывает скилл при сборке машины; спека задаёт правило соответствия,
  а не сами детали.

## 2. Данные и проверка

**Соответствие** — данные pack'а `packs/tochka-sborki/course/assembly-map.ts` (паттерн `@pack/course/*` со стабом движка
`lib/course/assembly-map.ts`): узел на каждый модуль с подписью RU/EN, для каждого юнита — id детали или `'node'`, подпись
детали RU/EN. Один файл на оба языка, ключи — слаги. У pack'ов без картины (living-practice, шаблон) — пустое соответствие,
чтобы стаб резолвился.

**Разделение:**
- движок: копия библиотеки Anatomy `lib/iso-kit/` (из `kit/` на закреплённом коммите, MIT, лицензия рядом), обёртка
  картины, расчёт состояний, миниатюра юнита — `lib/assembly/`, `components/assembly/`;
- pack: геометрия машины `packs/tochka-sborki/assembly/machine.tsx` (экспортирует компонент и список id деталей и узлов)
  и файл соответствия;
- флаг `COURSE.features.assemblyMap`: Точка Сборки — `true`, living-practice и `LMS/_template` — `false`. Лаборатория
  потом получает свою машину тем же движком.

**Состояния — по деталям:**
- `built` — юнит детали пройден; `ghost` — не пройден (рисуется контуром);
- юнит `'node'` пройден — корпус узла `built`;
- `current` — деталь (или узел) текущего юнита, поверх `built`/`ghost`;
- узел собран, когда собраны все его детали и корпус; частично пройденный модуль выглядит частично собранным;
- источник — `unit_progress` (`lib/unit-progress.ts`): localStorage, у вошедшего сверенный с сервером, в зеркале — локальный.

Расчёт — чистая функция `assemblyState(map, progress, current?) → { parts: Record<id, 'built'|'ghost'>, nodes:
Record<nodeId, { built: number; total: number }>, current: id | null }`.

**Тест** `lib/content/assembly-integrity.test.ts`, `describe.runIf(COURSE.features.assemblyMap)`:
- у каждого юнита из `_meta.json` обоих языков есть запись соответствия, лишних записей нет;
- каждый id детали из соответствия есть в геометрии машины, а у каждой детали машины есть юнит (сирот нет);
- у каждого модуля из контента есть узел; опциональные узлы ⇔ `OPTIONAL_MODULE_SLUGS`;
- у каждого узла и каждой детали есть подписи RU и EN.
Новый юнит без детали — красный тест.

## 3. Интерфейс и поведение

- **Первый юнит модуля** (поправка плана 2026-10-12: URL модуля — не страница, а `ModuleRedirect` на первый непройденный
  юнит; «страница модуля» = первый юнит, где уже стоит `ModuleObjectives`): картина во всю ширину, узел модуля подсвечен.
  Наведение/фокус на узел — подпись; клик — URL модуля через роутер Next (basePath зеркала и `/praktika` — сам).
- **Шапка юнита** (`components/pages/unit-page.tsx`): миниатюра под заголовком с подписью «Ты собираешь: <узел> → <деталь>»
  (для `'node'` — только узел). Клик открывает полную картину во всплывающем окне: Esc и кнопка закрытия, фокус
  возвращается на миниатюру. На телефоне миниатюра на всю ширину, ниже по высоте.
- **Один рисунок на страницу:** SVG рендерится при сборке (SSG) один раз; миниатюра — тот же рисунок, уменьшенный
  стилями; полная версия во всплывающем окне монтируется только при открытии. В браузере на картину накладывается только
  состояние (классы/атрибуты по `assemblyState`).
- **Движение:** только спокойная пульсация `current`; при `prefers-reduced-motion` и в режиме экономии трафика (`useLite`)
  картина неподвижна. Без WebGL и 3D.
- **Темы:** светлая и тёмная по `data-theme` курса.
- **Доступность:** `role="img"`, `<title>` и `<desc>` («Собрано 7 из 12 узлов, сейчас — Pipeline»); рядом визуально скрытый
  список узлов с состояниями; узлы фокусируются с клавиатуры.
- **Зеркало и двери:** картина не ходит в API; в зеркале — с локальным прогрессом. Картина — часть страницы юнита внутри
  `UnitGates`: за дверью (auth/intake) её не видно, как и остальной страницы (поправка плана 2026-10-12).
- **Бюджет веса:** разметка картины ≤ 300 КБ без сжатия (было 200; поднято владельцем 2026-10-12 — детализация упиралась в бюджет). Меряет тест рендера полной картины (`assembly-figure.test.tsx`):
  на основном сайте юниты за дверью (AuthGuard/IntakeGuard рендерят содержимое только в браузере), и в HTML картины нет —
  postbuild-скрипт тогда громко пишет «не измерено в HTML»; там, где картина в HTML есть (зеркало), превышение даёт код 1
  (поправка при исполнении задачи 5, 2026-10-12; замер зеркала: 116 страниц, тяжелейшая 23,5 КБ).

## 4. Порядок работ

1. **Гейты скилла** (из intake LMS#36): SecOps-ревью `SKILL.md`, `references/`, `scripts/`; `publish.mjs` и абзац
   о публикации в галерею — отключить; закрепление на SHA; смоук на ноуте Windows (сборка `examples/dial-indicator` +
   `scripts/capture.mjs`, риск issue #50). Затем копия `kit/` в `lib/iso-kit/` с лицензией. Поправка плана 2026-10-12:
   черновой машине библиотека не нужна (свой проектор `lib/assembly/iso.ts`), поэтому гейты и копия идут после шага 2,
   перед шагом 3.
2. **Движок с черновой машиной:** типы, соответствие для всех 58 юнитов, `assemblyState`, обёртка, миниатюра,
   всплывающее окно, флаг, тест соответствия, проверка веса. Черновая машина — простые изометрические блоки на каждый узел
   и деталь с теми же id. Механика проверяема и может выйти на прод до настоящего рисунка.
3. **Настоящая машина:** скилл Anatomy строит `machine.tsx` по тем же id; обязательны его `audit.mjs` и `lines.mjs`;
   снимки в обеих темах читает агент, затем показывает владельцу. Замена черновика — один файл pack'а.
4. **Встраивание и живая проверка:** страницы модулей и юнитов RU и EN; после деплоя — прод и зеркало в браузере.

**Стоп-критерий шага 3:** машина не проходит проверки скилла, или сборка не уложилась в три рабочие сессии, или владелец
не видит, что она объясняет лучше текста. Тогда шаг 3 сворачивается; черновая машина остаётся, решение владельца —
оставить её или выключить флаг.

**Тесты:** `assemblyState` (built/ghost/current, частично собранный узел, юнит `'node'`, пустой прогресс, неизвестный слаг);
рендер обёртки и миниатюры (`renderToStaticMarkup`, node-окружение vitest); соответствие; доступность (title/desc, скрытый
список, фокусируемость). Vitest и `tsc` под оба pack'а: у living-practice флаг выключен — картины на страницах нет.
