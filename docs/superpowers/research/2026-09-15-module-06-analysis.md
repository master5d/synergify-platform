По `_meta.json`: «Pipeline автоматизации» / «Automation Pipeline», «Строим первый практический workflow», заявлено 60 мин, level 6. Четыре юнита, у каждого фазы Kolb: activation → reflection → concept → practice.

## 4. Место в дуге курса

Макрофаза (`web/lib/rpg/macro-phases.ts:26`): 04 prompt → 05 context/memory → **06 pipeline**. Трансформация (`transformations.ts:19`): «данные разрознены → строю pipeline сырое → инсайт».

- **05 → 06.** Связь слабая. 05 заканчивается памятью и параллельными агентами, 06 начинается заново с «вспомни поток». Ни CLAUDE.md, ни память из 05 в pipeline 06 не используются. Упущенная связка: промпт u3 можно было бы положить как проектный файл или шаблон, который агент читает сам.
- **06 → 07.** Связь явная, но односторонняя. u4 говорит «Hooks для событий агента (модуль 07)» и «это твой roadmap для модуля 07». 07/u5-practice:26 подтверждает: «Модуль 06: построил первый pipeline». В 07 превращение повторяющегося промпта в Skill (о4 модуля 07) — **естественное продолжение u3-prompt.md из 06**, но 07 на этот файл не ссылается, а 07/u3-hooks про 06 не упоминает вовсе.
- **06 ↔ 08 (перекрытие).** В 08 цель o3: «какие решения в архитектуре pipeline защищают его от сбоя: маленькие шаги, **идемпотентность, разделение trigger и action**». В u3 разобран реальный n8n-кейс ENERV (Gmail trigger → router → parse → …, idempotency через labels). 08/u1 даёт критерий «данные из 3+ источников → нужен pipeline, не промпт».
  - 06 закладывает словарь (trigger/action/condition). 08 даёт настоящий production-pipeline. Condition «дубли» из 06 и есть идемпотентность в 08, но **мостика нет**: 08 не называет это продолжением 06, а 06 не обещает этого 08.
  - Дублирование умеренное, а не лишнее. Настоящий пробел **между** модулями: ни один модуль не проводит ученика через первый реально запускаемый по расписанию или событию pipeline. 06 такой pipeline только описывает. 08 показывает чужой (ENERV) и в практике просит «спецификацию до кода». Единственное место, где что-то реально автоматизируется, — бонус-упражнение в `exercises.mdx:514-535` («Построить одну автоматизацию», рецепты из `automation-recipes.md`). Оно лежит вне модулей.

## 5. Что осталось плохого после последних правок (по приоритету)

**P1. Влияет на ученика и данные**
1. **Каталог воркера говорит «работа с аудио»** (`workers/src/lib/course-catalog.ts:14`). Это портит классификацию спроса (раздел 2). Правка в одну строку, и она не зависит от решения по slug.
2. **Модуль ничего не автоматизирует.** Описание «первый практический workflow» и roadmap («первый автоматизированный workflow экономящий 2–5 ч/нед», `roadmap.mdx:186-188`) не выполняются. Цели o2/o3 закрыты только теоретически. Минимальная починка: одна выполнимая практика со schedule или event-trigger. Например, `/schedule` или cron либо n8n/Make по рецепту из `automation-recipes.md`, или хотя бы «сохрани промпт как Skill и вызови его командой».

Промпт на несколько URL в чате без браузинга даст галлюцинацию по трём ссылкам сразу, а это ровно тот провал, от которого страхует u1.
4. **Firecrawl висит без опоры.** Он есть в callout u1:8, в примере «наш pipeline сегодня» и в вопросе c1, но нигде не устанавливается и не используется. В Claude Code есть встроенный WebFetch. - `localStorage.unit_progress` имеет форму `{moduleSlug: {unitSlug: true}}` (`web/lib/unit-progress.ts`). Сервер его не видит, поэтому нужен клиентский алиас: при чтении в `parseProgress` сливать `06-audio-pipeline` в новый ключ. Иначе галочки юнитов 06 пропадут у всех.
- Другие сторы (`daily_quests`, `cs_wallet`, `niche_dungeon`, `pacing`) могут тоже хранить slug модуля. **Не проверял, это нужно сделать до переименования.**

**Аналитика.** Plausible `self_check_answered` шлёт `module: moduleSlug` (`web/lib/self-check.ts:17`). Серия разойдётся на две. Данных копится всего с 2026-09-14, так что потеря почти нулевая.

**Редиректы.** `web/public/_redirects` существует (формат Cloudflare, числится в `public-owned.json`). Нужны правила:
```
/lessons/06-audio-pipeline/*    /lessons/<новый>/:splat    301
/en/lessons/06-audio-pipeline/* /en/lessons/<новый>/:splat 301
```
Они же спасают ссылки из уже отправленных nudge- и телеграм-сообщений.

**Внешнее.** В mc_hub живых ссылок нет: slug встречается только в `CLAUDE.md`, `docs/**` и `feedback/feedback.jsonl`. В `academy/` и `dashboard/` lms-engine упоминаний нет. Документы lms-engine (`BACKLOG.md:139`, планы, легаси `LMS/tochka-sborki/*.md`) обновлять по желанию. Сертификат (`course/certificate.ts`) slug не содержит. Walkthrough `pipeline-ru` / `pipeline-en` от slug не зависит.

**Что нужно для безопасного переименования.** Один атомарный PR:
1. `git mv` папок ru и en.
2. Правка ~12 TS/JS-файлов и 9 JSON скинов (сначала сгенерировать `gen-skins.mjs`, потом проверить тестами).
3. Две ссылки в roadmap.
4. `_redirects`.
5. Клиентский алиас в `unit-progress` (и в других сторах, если найдутся).
6. D1-миграция `progress` (+ `content_demand`), идёт одновременно с деплоем воркера. Иначе в окне между деплоями admission закрыт.
7. Приёмка: старый URL отдаёт 301; admission для тестового пользователя с прогрессом по старому slug; галочки юнитов на месте.

Оценка: 0.5–1 день плюс риск на стыке «воркер ↔ D1 ↔ статика».

## 7. Варианты

| | (a) Оставить slug, чистить смысл | (b) Переименовать с редиректами и миграцией | (c) Перестроить модуль |
|---|---|---|---|
| Что делаем | Каталог воркера (1 строка), 4–5 строк скинов, секция roadmap, длительности, страховка чата в u3, Firecrawl → «инструмент чтения страниц» | Всё из (a) + раздел 6 | Всё из (a); добавить в 06 **выполнимый шаг автоматизации** (schedule или event: `/schedule`, cron, n8n/Make по рецепту, или Skill-вызов) и мостики 06→07→08. Отдельный аудио/голосовой урок **не** рекомендую, см. ниже |
| Трудозатраты | 1–2 ч | +0.5–1 день | 1–2 дня текста (ru+en), новые self-check, прогон гварда alignment |
| Риск | ≈0 | Средний: admission и прогресс, окно деплоя, клиентские сторы | Низкий по коду, средний по методике (новая практика должна работать у всех стеков) |
| Что получает ученик | Никаких ложных обещаний «звукового pipeline»; roadmap совпадает с уроками | Красивый URL. Больше ничего: заголовок и так верный, slug видит только адресная строка | Реальный первый автоматический pipeline: цели o2/o3 закрываются руками, обещание roadmap «2–5 ч/нед» становится честным |

Почему не аудио-урок в (c). Автоматизация встреч (аудио → транскрипт → задачи) уже есть как пример в u2 и u4 и как Skill `/meeting-summary` в 07. Работа с аудио как источником есть в 09. Голос как навык — в `/speech`. Отдельный аудио-урок подогнал бы контент под случайное имя, а не под потребность курса.

**Рекомендация: (a) сейчас, (c) следующим шагом, (b) не делать отдельно.** Переименование стоит своего риска только вместе с большой перестройкой. Например, если когда-нибудь 06 и 08 объединят в один трек «pipeline → агент», тогда меняется номер и смысл, и миграцию делают один раз под новую структуру. Пока slug виден только в URL, а решение владельца «не менять» (BACKLOG:139) остаётся в силе, достаточно убрать места, где имя продолжает врать от лица модуля.
