## LMS#1 — «Tochka + blog»: «С чего начать погружение в ИИ»

**Источник:** Evernote share f341a2ea-d2a0-f9ac-3349-de653f01ff37 (блокнот Home, без тегов, медиа нет;
создана 2026-05-07). Заголовок заметки — приписка владельца: «Tochka + blog».

**Досье:** текст поста — не владельца. «Мой гайд… чат-бот, за токены которого я сам плачу» — голос
автора канала. Пост: не опоздали, но начните с базы (токен, контекстное окно, температура, чем модели
отличаются, промпт vs контекстная инженерия, агенты), без математики и кода, на первом этапе ничего не
платить; бесплатный гайд-бот «в первом комментарии»; ссылка на сборник t.me/prompt_design/2093.

**Реальность:** канал живой — «Силиконовый Мешок», @prompt_design, ~85.6K, админ @artem_subbotin
(веб-превью t.me/s/). Пост 2093 — серия «Для начинающих»: мини-курс в боте @promptdesignbot
(мини-курс + встроенный чат), гайд по промптингу (2057), полный гайд по Claude (2008), PDF по
инструментам Claude (2093). Соседние посты продают офлайн-ивент со скидкой и платное сообщество —
«бесплатно без продаж» здесь верхушка воронки. Артефакт проверяем, лицензии нет (контент, код не берём).
Канал уже встречался: NAUTILUS#103 (2074), ProductOps O-4 (2136), 2026-09-10 (2372).

**Дедуп:** GUID по `Efforts/**/*intake*.md` — повторов нет. В LF текста нет. В ТС: модули 00–09
(kickstart → agent-engineering); «контекст vs промпт» есть (05/u2), агенты есть (08); «температуры» нет
нигде, токены — только шпаргалка («1 токен ≈ 4 символа») и строка roadmap «минимальный словарь».

**Вердикт:** `pattern-only`.
- **ТС** — (1) юнит-«азбука» до модуля 0: словарь новичка одним экраном — реальный пробел;
  (2) рамка входа «бесплатно, без встроенных продаж», у автора — рычаг доверия. → BACKLOG, owner-gated.
- **LMS/академия** — (3) курс, упакованный в Telegram-бота с чатом по материалам: второй канал доставки
  pack'а. У платформы есть telegram-auth/webhook и llm-service; движку нужен режим «бот как плеер курса».
  → BACKLOG, owner-gated, спека до кода. (4) Серия «Для начинающих» как сборник скачиваемых гайдов —
  у ТС уже есть cheatsheet/exercises: `already covered`.
- **Блог** — (5) пост «С чего начать» с CTA на ТС — только через LF (HARD RULE), чужой текст не
  переносим. → BACKLOG, owner-gated.

**Паттерны (лаба):** «люди = агенты» — «начни с базы до того, как платить» = лестница онбординга
«сначала бесплатные пулы» — это уже политика гейтвея. Тьютор с чатом по корпусу уже есть
(`/tutor` по Vibe-Street). Новых паттернов для лабы нет. Не брать: PDF-гайды канала как источник для
курса — контент чужой, лицензии нет.

## LMS#3 — «Tochka»: Kajabi vs Thinkific (блог Kajabi)

**Источник:** Evernote share e4f1daf3-3cc2-4280-9f14-52d6cf38c9b0 (создана 2026-05-04), веб-клип статьи
блога Kajabi «Kajabi vs Thinkific for Course Creators: What Matters When Courses Are Your Business»
(2026-03-26). Одна картинка — декоративный баннер с двумя логотипами, текста нет; сконвертирована в
`NAUTILUS/data/intake-media/e4f1daf3-3cc2-4280-9f14-52d6cf38c9b0/` (banner.png + banner.md + MANIFEST.md).

**Досье:** тезис статьи: курс-билдеры у обоих равны, разница в том, что вокруг курса — маркетинг, email,
автоматизации, checkout, аналитика, рост от одного курса до «knowledge business» без внешних тулов.
Конкретика: drip по календарной дате (для когорт), аналитика вовлечения и отвала по урокам, автоматизации
по поведению на общих данных («закончил модуль 3 → письмо-апселл на advanced-курс» без Zapier), нативные
upsell / order bump / рассрочка / подписки / партнёрка, AI «Cofounder» (что преподавать, структура, копирайт,
цена, запуск — по данным уже построенного на платформе), coaching / community / memberships.

**Реальность:** источник настоящий, но это **вендорский материал**: сравнение пишет одна из сторон, в тексте
промо-вставка «3 месяца Kajabi + Cofounder за $99». Проверяемого артефакта нет — фичи конкурента по его
словам. Лицензия не нужна: код и контент не берём.

**Дедуп:** GUID — повторов нет. Kajabi и Thinkific в лабе не разбирались, но категорию закрывает
LearnWorlds-харвест (NAUTILUS `docs/superpowers/research/2026-08-06-learnworlds-harvest.md`, приватный):
нативный e-commerce (п.8), AI-ассистент автора (п.1, 12–15), когорта + drip + сертификат (п.18),
community (п.7), три типа email-дрипов (п.23–25). Против платформы:
- **есть:** D1 = источник правды (users, progress с `completed_at`, purchases), Listmonk-зеркало лидов
  (`workers/src/lib/crm.ts`), Stripe checkout (`handlers/checkout.ts`), сертификат (`features.certificate`),
  авторинг-цепочка plan→scaffold.
- **нет:** реакции на события прогресса (Listmonk получает только лида при входе); воронки по урокам
  (`/api/admin/stats` отдаёт только три счётчика: users, learners, анкеты); календарного drip для когорты
  (`lib/pacing` — личный ритм ученика в браузере; когорта записана в спеке платформы как бэклог Ф2).

**Вердикт:** `pattern-only`.
- **ТС** — (1) **событие прогресса → письмо**: «закончил модуль N / весь курс» → сегмент Listmonk →
  письмо. Первое применение — предложить только что решённый модуль «Обучение моделей» (advanced) тем, кто
  закончил агентную часть. Данные у нас уже в одном месте (D1), Zapier не нужен — нужен один хук в
  `handleComplete`. → BACKLOG, owner-gated.
- **LMS/академия** — (2) **воронка отвала по урокам** в `/api/admin/stats`: сколько дошло до каждого
  юнита и где бросили — по всем pack'ам через `progress.course`. → BACKLOG, owner-gated. (3) Календарный drip
  для когорт — уже в бэклоге платформы (cohort-акселератор, Ф2): `already covered`. Upsell / order bump /
  рассрочка / партнёрка / memberships — не берём, пока нет второго платного продукта. AI «Cofounder» —
  `already covered`: авторинг-цепочка + агент автора (sovereign authoring, прозу пишет агент владельца).

**Паттерны (лаба):** «люди = агенты»: «событие жизненного цикла → следующее действие» в лабе уже есть
(labwatch, хуки SessionStart). Новых паттернов нет. Не брать: оценку «Kajabi сильнее» как факт — это текст

## LMS#5 — «tochka sborki / logos foundry»: Netguru «Non-Technical Introduction to AI Fundamentals»

**Источник:** Evernote share b8a2053d-c167-48c1-9131-f5b55adf24d1 (создана 2026-03-11), веб-клип статьи блога
Netguru (автор Krystian Bergmann, «Updated Aug 29, 2025», раздел Business Strategy & Growth). Заголовок —
приписка владельца: адресовано и ТС, и Logos Foundry. Одна картинка — декоративный арт без текста;
сконвертирована в `NAUTILUS/data/intake-media/b8a2053d-c167-48c1-9131-f5b55adf24d1/` (ai.md + MANIFEST.md).

**Досье:** вводная для нетехнарей. Рамка: Кондратьев (ИИ = новая длинная волна), hype cycle Gartner,
Гибсон («будущее уже здесь, просто неравномерно распределено»), «crossing the chasm» для генеративного ИИ.
Словарь: ИИ как зонтик ⊃ ML ⊃ deep learning; computer vision; NLP. Таксономия алгоритмов (регрессия,
классификация, кластеризация, временные ряды, аномалии, ранжирование, рекомендации, генерация,
оптимизация). Проектирование ИИ-продукта: 80% времени — разметка и подготовка данных; 7 шагов ML-проекта
(сбор → предобработка → выбор модели → обучение → тест → тюнинг → предсказание); design thinking vs ML.
LLM: GPT, attention («Attention is All You Need», 2017), ограничения (враньё, предвзятость, математика),
облачные vs локальные модели. Мегатренды, в т.ч. образование (Ethan Mollick). Финал — продажа услуг Netguru.

**Реальность:** автор и агентство настоящие, но это **контент-маркетинг агентства**, и он **протух**:
написан в 2023-м («GPT-4 — самая мощная LLM на 20.10.2023», GPT-3.5 Turbo как вариант), правка 2025 года

  (1) анализ задачи и разрыва (иерархический task analysis, Dick & Carey); (2) «учить или чинить среду» — модель
  Behaviour Engineering Гилберта (1978): данные, ресурсы, стимулы, знания, способности, мотивы; (3) проверка
  доступности по WCAG 2.1 AA; (4) аудит сценария урока по 12 мультимедийным принципам Майера (когнитивная нагрузка);
  (5) **constructive alignment** Биггса (1996): каждый вопрос проверки прямо отражает заявленную цель обучения.
- **Alcock** — человек пишет стандарт и 3–5 целей простым языком, кладёт их в тетрадку двумя источниками и получает
  двадцать разных видов проверок; каждый вопрос прослеживается до текста цели.
- **Kronberg** — обзор NotebookLM 2026 (поиск источников вопросом, Deep Research в тетрадке).
- **LearnWorlds** — слоган.

**Реальность:** все три статьи настоящие, авторы — практики (Hardman — известный дизайнер обучения, Alcock —
учитель). Цитируемые модели — классика дизайна обучения (Биггс, Майер, Гилберт, Dick & Carey, WCAG), проверяются по
первоисточникам. Статьи — чужой текст, берём методы, не текст.

**Дедуп:** GUID — повторов нет.
- **Цели модуля в ТС:** у модуля есть только однострочное `description` в `_meta.json` (главная, дерево курса,
  SEO). Блока «цели» на входе в модуль нет. Честный контракт «Будет / Не будет» (`lib/content/will-wont.ts`) есть,
  но только на уровне всего курса (`course-intro`). При этом **авторинг уже требует цель у каждого юнита**
  (`lib/authoring/course-plan-prompt.ts`, поле `objective` в outline), а у курса риторики `objective` урока
  выводится (`lesson-prose.tsx`, `speech-syllabus.tsx`). То есть поле в модели есть, до модулей ТС оно не доезжает.
- **Проверки из целей:** мини-проверки «проверь себя» уже приняты (LMS#8), педагогический блок ревью урока — тоже
  (LMS#7). Связки «вопрос ↔ цель» пока нигде нет.
- **WCAG** — уже в `design-audit` (контраст WCAG): `already covered`. **Майер** — в ревью урока нет.
- **NotebookLM-гайд (Kronberg)** — модуль ТС 09 целиком про тетрадку: `already covered`. **LearnWorlds** — харвест.

**Вердикт:**
- **ТС** — **идея владельца `adopt`** (ждёт подтверждения): блок «Цели модуля» в начале каждого модуля. 3–5
  проверяемых целей глаголом действия («соберёшь…», «отличишь…»), поле `objectives` в `_meta.json` модуля, рендер
  на входе в модуль и в дереве курса. Источник целей — уже существующее поле `objective` из outline авторинга (не
  писать заново, а донести). Пилот — модули 00 и 04. Стоп-критерий: если цели не удаётся сформулировать
  проверяемыми (каждую — хотя бы одним вопросом «проверь себя») — значит, модуль не про то, что обещает, и это
  находка для правки модуля, а не для блока.
- **LMS** — `pattern-only`: (1) **constructive alignment как гвард**: у каждой мини-проверки (LMS#8) есть ссылка
  на цель модуля, у каждой цели — хотя бы одна проверка; тест движка ловит висящие цели и вопросы без цели;
  (2) **принципы Майера** — в педагогический блок ревью урока (LMS#7). Формулировки свои. → BACKLOG.
- **Лаба** — паттернов нет (source-grounded тьютор уже есть).

**Паттерны (не брать):** «20 видов проверок из двух документов» (Alcock) — для курса одного автора избыточно,
берём только принцип «каждый вопрос прослеживается до цели».

**Решение владельца (2026-09-14):** гвард constructive alignment — берём; 12 принципов Майера в ревью урока —
берём; цели модуля — **сразу на весь LMS** (фича ядра для всех pack'ов, поле обязательное в контракте pack'а),
пилот на 00/04 отменён.
