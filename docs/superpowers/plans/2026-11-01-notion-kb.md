# База знаний «Точки Сборки» в Notion — план реализации

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** книга (модули → юниты) и словарь понятий «Точки Сборки» в Notion-пространстве «RAM», собранные из того же коммита, что сайт и зеркало, задачей `deploy-notion`.

**Architecture:** движковый генератор `lib/notion-kb/` разбирает MDX (`remark-mdx`) и пишет Notion-flavored Markdown v2; компоненты курса — по таблице правил (блоки Notion или ссылка «интерактив — на сайте»), первое упоминание понятия — ссылка на его страничку. Синхронизация односторонняя: обычные страницы (без баз данных) под служебной страницей S; страница переписывается целиком (`PATCH /v1/pages/{id}/markdown`, `replace_content`) только при смене хеша; соответствие ключ → id, хеши и якоря — в манифесте на непубликуемой странице под S. Порядок: скелет → корзина → юниты → якоря заголовков → понятия → корень со штампом. CLI `scripts/notion-kb.ts` идёт нативным Node 24 без сборки (как `gen-lesson-views.ts`); данные pack'а — `packs/tochka-sborki/{concepts.ts,notion-kb.config.ts}`.

**Tech Stack:** TypeScript (type stripping Node 24), unified + remark-parse + remark-mdx + remark-gfm, mdast-util-to-markdown + mdast-util-gfm, Vitest, Notion REST API (`Notion-Version: 2026-03-11`, markdown v2), GitHub Actions.

**Spec:** `docs/superpowers/specs/2026-11-01-notion-kb-design.md`

Рабочая папка команд, если не сказано иное, — `LMS/tochka-sborki/web/` в worktree `C:\telo\Efforts\On\lms-engine\.worktrees\notion-kb` (ветка `feat/notion-kb` от `origin/main`). ## Решения плана (спека оставила их builder'у)

1. В Notion — обычные подстраницы, без баз данных. Порядок детей задают теги `<page url>` в markdown родителя. Notion сам отказывает в записи, которая удалила бы подстраницу: `allow_deleting_content` не передаём.
2. Соответствие ключ → страница хранится в манифесте на служебной странице. Отсюда уточнение шагов владельца § 8. Владелец создаёт и подключает пустую **служебную** страницу S, её не публикуют. Первая синхронизация создаёт под S корень базы K и страницу манифеста. Публикуется K.
3. «Подробно» ведёт якорем `#<id блока>` на заголовок юнита. id заголовков читаются после записи юнита, поэтому понятия пишутся после юнитов. Якоря нет — ссылка ведёт на юнит, в логе громкое предупреждение.
4. Штамп. На корне — sha текущей сборки, корень переписывается на каждом новом коммите. На прочих страницах — sha сборки, которая последней меняла их текст. Повторный прогон того же коммита ничего не пишет (спека, «Проверка» п. 2).
5. Ссылки на понятия — текстом: `[форма слова](https://www.notion.so/<id>)`, а не `<mention>`. Упоминание показывает заголовок страницы, и русская форма слова теряется.
6. Из 22 ссылок «на модуль» уточняются 6 — там, где фраза отсылает к месту, объяснённому в конкретном юните. Остаются на модуль четыре ссылки-обзора («лестница курса», «модуль 11 разберёт…») и 12 строк дорожной карты: их адрес — именно модуль.
7. Поправка к спеке § 8 по справочнику API вносится тем же коммитом, что план. Лимит включает второй **участник** любой роли, а не только владелец.

## Global Constraints

- Notion API: `https://api.notion.com/v1`, заголовок `Notion-Version: 2026-03-11`, `markdown_version: "v2"` в каждом markdown-запросе, запись — `replace_content` целиком.
- Темп и сеть: ≤ 3 запросов/с (интервал ≥ 334 мс), таймаут 30 с на запрос, до 5 попыток. 429 — ждать `Retry-After` (≤ 60 с). Повтор с паузой 1-2-4-8 с: 500/502/503/504/529 и сетевые сбои, только у идемпотентных вызовов. `createPage` при таймауте или 504 вслепую не повторяется.
- «RAM» — Free с одним участником, блоки без лимита. Второй участник любой роли (гости не считаются) включает пожизненный лимит 1 000 блоков: после трёх дней отсрочки запись получает 403 `restricted_resource` с `additional_data.block_limit = "block_creation"`, удаление ёмкость не возвращает. Такой ответ — отдельное сообщение и выход 1.
- Токен — только env `NOTION_KB_TOKEN` (секрет Actions и BWS): не в argv, не в логах, не в тексте ошибок.
- В коде нет LLM-вызовов (sovereign authoring из `CLAUDE.md`).
- Нативный Node: в `lib/notion-kb/` и во всём, что тянет CLI, значимые импорты только относительные (без `@/`, `@pack/`). Типы — `import type …` целым оператором. Запрещены enum, namespace, parameter properties (`constructor(readonly x)`), `import x = require`.

```ts
import { describe, it, expect } from 'vitest'
import { join } from 'node:path'
import { pathToFileURL } from 'node:url'
import { validateConcepts, linkFirstMentions, plainText, findOccurrences, BOUNDARY_BEFORE as B, BOUNDARY_AFTER as A } from './concepts'
import { parseMdx, toNotionMarkdown } from './md'
import type { Concept } from './types'
import { PACK_SLUG, PACK_DIR } from '../pack'

const re = (s: string, f = 'i') => new RegExp(`${B}(?:${s})${A}`, f)
const mk = (id: string, ru: string, en: string, forms: [string, string], unit: string): Concept => ({
  id, term: { ru, en }, forms: { ru: re(forms[0]), en: re(forms[1]) },
  short: { ru: `${ru} — это.`, en: `${en} is.` }, source: { unit, heading: { ru: ru, en: en } }, related: [],
})
const STATE = mk('state-md', 'STATE.md', 'STATE.md', ['STATE\\.md', 'STATE\\.md'], '01-alpha/u2-deep')
const AGENT = mk('agent', 'агент', 'agent', ['агент(?:а|у|ом|е|ы|ов|ам|ами|ах)?', 'agents?'], '01-alpha/u1-start')
const AI_AGENT = mk('ai-agent', 'AI-агент', 'AI agent', ['AI-агент(?:а|у|ом|е|ы|ов)?', 'AI agents?'], '01-alpha/u1-start')
const render = (src: string, unitKey: string | null = '02-beta/u1-next', locale: 'ru' | 'en' = 'ru') => {
  const tree = parseMdx(src)
  linkFirstMentions(tree, { concepts: [STATE, AGENT, AI_AGENT], locale, unitKey, href: (id) => `https://www.notion.so/${id}` })
  return toNotionMarkdown(tree)
}

describe('validateConcepts', () => {
  it('чистый список — без ошибок', () => expect(validateConcepts([STATE, AGENT, AI_AGENT])).toEqual([]))
  it.each([
    ['повтор id', [STATE, STATE], /state-md/],
    ['неизвестный related', [{ ...STATE, related: ['nope'] }], /related/],
    ['форма без границ слова', [{ ...STATE, forms: { ru: /STATE\.md/i, en: STATE.forms.en } }], /границ/],
    ['флаг g у формы', [{ ...STATE, forms: { ru: re('STATE\\.md', 'gi'), en: STATE.forms.en } }], /флаг/],
    ['пустой short.en', [{ ...STATE, short: { ru: 'x', en: '' } }], /short\.en/],
    ['id не kebab-case', [{ ...STATE, id: 'State_MD' }], /id/],
    ['«Коротко» длиннее 300 знаков', [{ ...STATE, short: { ru: 'а'.repeat(301), en: 'x' } }], /300/],
    ['повтор термина', [STATE, { ...AGENT, term: { ru: 'STATE.md', en: 'agent' } }], /term/],
  ])('%s', (_n, list, rx) => expect(validateConcepts(list as Concept[]).join('\n')).toMatch(rx))
})

describe('linkFirstMentions', () => {
  it('первое упоминание — ссылка, второе — текст', () => {
    expect(render('Открой STATE.md. Потом снова STATE.md.')).toBe('Открой [STATE.md](https://www.notion.so/state-md). Потом снова STATE.md.')
  })
  it('код, inline-код, ссылки и заголовки не трогает', () => {
    const out = render('## STATE.md\n\n`STATE.md` и [STATE.md](https://x.y)\n\n```\nSTATE.md\n```\n\nпотом STATE.md')
    expect(out.match(/\(https:\/\/www\.notion\.so\/state-md\)/g)).toHaveLength(1)
    expect(out).toContain('потом [STATE.md](https://www.notion.so/state-md)')
  })
  it('длинная форма побеждает короткую', () => expect(render('Наш AI-агент работает')).toContain('[AI-агент](https://www.notion.so/ai-agent)'))
  it('в юните-источнике понятие не ссылается само на себя', () => expect(render('Открой STATE.md', '01-alpha/u2-deep')).toBe('Открой STATE.md'))
  it('заглавная в начале фразы — тоже упоминание', () => expect(render('Агент ответил')).toContain('[Агент](https://www.notion.so/agent)'))
  it('слово внутри другого слова — не упоминание', () => expect(render('субагент ответил')).toBe('субагент ответил'))
  it('EN-страница ищет EN-формы', () => expect(render('Two agents talk', null, 'en')).toContain('[agents](https://www.notion.so/agent)'))
})

describe('plainText и findOccurrences', () => {
  it('без забора кода, с текстом inline-кода и детей компонентов', () => {
    expect(plainText('Текст `код`\n\n```\nне это\n```\n\n<OsBlock os="mac">\n\nвнутри\n\n</OsBlock>')).toBe('Текст код внутри')
  })
  it('юниты с упоминанием — в порядке входа', () => {
    expect(findOccurrences([STATE], 'ru', [{ key: 'a', text: 'про STATE.md' }, { key: 'b', text: 'нет' }, { key: 'c', text: 'и STATE.md' }]).get('state-md')).toEqual(['a', 'c'])
  })
})

  })
})
```

  - `createNotionClient(opts: { token: string; fetchImpl?: typeof fetch; sleep?(ms: number): Promise<void>; now?(): number; timeoutMs?: number }): NotionApi`.

Запросы:

| метод | HTTP | тело / разбор |
|---|---|---|
| createPage | POST `/pages` | `{ parent: { type: 'page_id', page_id }, properties: { title: { title: [{ type: 'text', text: { content } }] } } }` → `id` |
| updateTitle | PATCH `/pages/{id}` | `{ properties: { title: … } }` |
| replaceMarkdown | PATCH `/pages/{id}/markdown` | `{ type: 'replace_content', replace_content: { new_str }, markdown_version: 'v2' }` |
| getMarkdown | GET `/pages/{id}/markdown?markdown_version=v2` | `{ markdown, truncated }` |
| trashPage | PATCH `/pages/{id}` | `{ in_trash: true }` |
| listChildren | GET `/blocks/{id}/children?page_size=100[&start_cursor=]` до `has_more: false` | `child_page.title`; `heading_1..4.rich_text[].plain_text`; прочее — `text: ''` |
| getPage | GET `/pages/{id}` | `{ publicUrl: public_url ?? null, inTrash: in_trash }` |
| searchPages | POST `/search` | `{ filter: { property: 'object', value: 'page' }, page_size: 100 }` → заголовок из `properties.title.title` |

Политика повторов — Global Constraints. У `createPage` 504, таймаут и сетевой сбой дают `NotionError` с `code 'uncertain'` без повтора; 429 и 529 повторяются (запрос не принят). 403 `restricted_resource` с `block_limit: 'block_creation'` → `blockLimit: true`, сообщение: «Notion: лимит блоков Free (restricted_resource). В «RAM» появился второй участник? Запись остановлена».

### Task 6: манифест и синхронизация (`manifest.ts`, `sync.ts`, `FakeNotion`)

**Files:**
- Create: `lib/notion-kb/manifest.ts`, `lib/notion-kb/sync.ts`, `lib/notion-kb/__fixtures__/fake-notion.ts`

**Interfaces:**
- Consumes:
  - из Task 1 — `parseMarkdown`, `notionUrl`, `anchorUrl`, типы;
  - из Task 3 — `STRINGS.stamp`;
  - из Task 4 — `KEY`, `buildSite`, `MINI_COURSE`;
  - из Task 5 — `NotionError`.
- Produces (`manifest.ts`):
  - `ManifestEntry = { id: string; p: string | null; th: string; ch: string | null }`. Здесь `p` — ключ родителя, `th`/`ch` — хеши заголовка и текста.
  - `Manifest = { v: 1; pages: Record<string, ManifestEntry>; anchors: Record<string, string> }`.
  - `EMPTY_MANIFEST`.
  - `MANIFEST_TITLE = 'notion-kb · manifest (не публиковать)'`.
  - `encodeManifest(m: Manifest, chunk = 1800): string`.
  - `decodeManifest(markdown: string): Manifest`.
- Produces (`sync.ts`):
  - `contentHash(title: string, md: string): string` — sha256 hex, 16 знаков.
  - `stampLine(l: Locale, sha: string, date: string): string` — `*<stamp>: <date> · <sha[0..7]>*`.
  - `SyncOptions = { sha: string; date: string; only?: string; log(line: string): void }`.
  - `SyncReport = { created: number; adopted: number; updated: number; retitled: number; trashed: number; unchanged: number; anchorMisses: string[] }`.
  - `syncSite(api: NotionApi, pages: SitePage[], concepts: Concept[], servicePageId: string, opts: SyncOptions): Promise<SyncReport>`.
  - `verifyRootStamp(api: NotionApi, rootId: string, sha7: string): Promise<boolean>`.
- Produces (`__fixtures__/fake-notion.ts`): `class FakeNotion implements NotionApi`.
  - Конструктор: `{ root: string; uncertainCreates?: Set<string> }`.
  - Поле `log: string[]` — изменяющие вызовы по порядку: `create <title>`, `replace <id>`, `title <id>`, `trash <id>`.
  - Методы: `live()`, `get(id)`, `idByTitle(title)`, `addManualChild(parentId, title)`, `setMarkdown(id, md)`.
  - `replaceMarkdown` отказывает (`NotionError` 400 `validation_error` с заголовками), если в markdown нет `<page url=…id…>` хотя бы одного живого ребёнка.
  - `listChildren` отдаёт живых детей и заголовки `^#{1,4} ` из текущего markdown; id заголовков новые после каждой записи.
  - `createPage` при первом создании заголовка из `uncertainCreates` создаёт страницу и всё равно бросает `uncertain`.
  - `created` в отчёте считает только страницы базы, без страницы манифеста.

Синхронизация, по шагам:
1. **Манифест.** Под S ищется подстраница `MANIFEST_TITLE`.
   - Есть → `decodeManifest(getMarkdown().markdown)`; `truncated` → ошибка.
   - Нет → создать, манифест пуст.
2. **Скелет.** Страницы идут в порядке `buildSite`. Для ключа, которого нет в манифесте:
   - родитель = `p ? pages[p].id : S`;
   - сначала искать живую подстраницу родителя с тем же заголовком, чьего id нет в манифесте (кэш детей на прогон), и принять её;
   - иначе создать; на `uncertain` — перечитать детей без кэша и принять найденную либо создать ещё раз;
   - у новой записи `th = contentHash(title, '')` и `ch: null`;
   - было изменение → записать манифест.
3. **Корзина**, только без `only`.
   - R — ключи манифеста, которых нет в наборе.
   - В корзину уходят те ключи из R, чей родитель не в R (вложенные уходят вместе с ним).
   - R и их якоря стираются из манифеста.
   - R не пуст → записать манифест.
4. **Текст (стадия `content`, корень — отдельно).**
   - Заголовок изменился → `updateTitle`.
   - `contentHash(title, md)` изменился → `replaceMarkdown(id, md + '\n\n' + stampLine)`.
   - Ошибка → `Error('запись <ключ> не удалась: <сообщение>')`.
5. **Якоря.** Для понятия и локали, чей юнит-источник есть в наборе: если юнит записан в шаге 4 или якоря нет → `listChildren(юнит)`.
   - Заголовок с тем же текстом (пробелы схлопнуты) → `anchors['<l>/<id>'] = id блока`.
   - Иначе → `anchorMisses`, якорь стирается.
6. **Понятия.** Как шаг 4, для стадии `concept`.
7. **Корень.** `md = root.markdown + штамп`; хеш считается **со** штампом.
8. Манифест менялся → записать.
9. Сверка штампа: `verifyRootStamp(...)` дал `false` → `Error('штамп корня не совпал с <sha7>')`.

Адреса при записи: `page(key)` = `notionUrl(manifest.pages[key].id)`, если ключ есть в манифесте, иначе `null`. Поэтому в `only`-режиме книга сохраняет теги ранее созданных модулей.
